# 规格体系审计与已执行简化

审计日期：2026-08-12  
范围：九份 `Request/*.md`、`docs/change-requests/`、基线导航、当前 OpenAPI/迁移/配置/测试入口。  
边界：未读取 `.env`、密钥、Token 或生产数据；旧文档只做字节级归档，不删除原始业务规则。

## 结论

当前主要问题不是缺文档，而是同一事实被同时写进需求、架构、API、数据库、页面、AI、测试、运维、计划和 CR。批准变更又以“顶部覆盖旧正文”的方式叠加，导致开发者必须人工计算有效合同。

应从“九份人工同步的 Markdown 合同”改为：

- 一份产品需求与 AC。
- 少量解释性设计文档。
- OpenAPI、Alembic、枚举/状态机、AI Policy、配置 Schema 等机器事实来源。
- 一份简短决策日志和一份当前范围表。

该结构已于 2026-08-12 落地：`Request/` 根目录只保留四份活跃规格，旧九份文档移入 `Request/archive/legacy-v1/` 并通过移动前后 SHA-256 对比确认字节不变。

## 高优先级问题

### 1. 有效规范是补丁栈

九份文档开头分别叠加 CR、snapshot、hash、Gate 和授权说明，并声明与后续正文冲突时以前置覆盖段为准。相同的 CR-003-R3 绑定句甚至出现在九份文档中。

用户影响：开发时间被消耗在解释文档优先级；实现旧字段或漏掉覆盖规则会造成接口和数据不兼容。

处理：批准内容必须合并进单一事实来源；正文不再保留“本节覆盖下文”。历史 CR 只留在决策日志/Git 历史。

### 2. 已出现直接契约冲突

- break-glass 顶部合同和 accepted Alembic 使用 `decided_by`，API/数据库旧正文仍写 `approved_by`。
- CR-004 顶部要求 Job `row_version`、`JOB_VERSION_CONFLICT`，且 retry 保持当前 attempt；FILE-007、AUDIT-007/008、OPS-001 旧正文仍使用旧 DTO 和递增 attempt 语义。
- 页面要求实现供应商确认，又明确 GAP-064 前不得实现或模拟。
- 审核状态机定义 `failed → queued`，却没有完整进入 `failed` 的边；取消状态在不同章节也不一致。

用户影响：前端、API、Service、迁移和测试不能从文档得到同一个行为。

处理：状态机、错误码、DTO 和字段只定义一次，并由机器测试投影到各消费者。

### 3. 目标设计、当前实现和运行授权混在一起

- API 文档把未冻结、未授权的 SUPP-003/CON-005 写成完整硬契约。
- 数据库文档把 57 表目标写成当前物理设计，但 accepted Alembic 当前只创建其中一部分。
- 运维文档给出不存在的 Compose/脚本并写成可执行 Runbook。
- AI 文档在 Provider、模型和阈值仍未签署时冻结大量预算、限流和传输参数。

用户影响：文档存在会被误报为代码已实现或环境已可运行。

处理：所有状态明确区分 `documented / implemented / verified / accepted`；未运行统一为 `NOT_RUN`。

### 4. 库存数量被错误提升为产品合同

57 张表、122 个 API 和 86 个工作包被多处固定，删除低价值接口、合并等价表或重新拆任务都必须触发大规模 CR。

用户影响：实现为了满足计数，而不是尽快形成可用业务闭环；安全的等价重构也被阻断。

处理：数量降级为自动盘点。产品只冻结业务对象身份、用户行为、权限、安全不变量和 AC。

### 5. P0 对独立开发者过大

当前 P0 同时包含认证、文件、合同/发票 AI、RAG/评测、审核编排、PDF/Excel、日志、Compose、职责分离与恢复；开发计划估算约 561 人日。

用户影响：项目长期停留在基础设施和小切片，难以尽早验证真实产品价值。

处理：交付顺序改为三层，不改变最终 P0 目标但改变进入路径：

1. `MVP vertical slice`：上传 → 一类财务文档 → 确定性规则 → 人工确认 → 报告。
2. `Beta`：补齐合同/发票/制度、RAG、版本链、职责分离和失败恢复。
3. `Production readiness`：真实扫描、Provider、性能、安全、备份恢复、部署和 UAT。

### 6. 测试与运维文档不能作为当前运行手册

- 测试方案重抄 AC-001～AC-016，并增加未定义的“五方签署”和大量全局阻断门禁。
- 运维说明内嵌完整 `.env`，已经与 `infra/env/.env.example` 漂移。
- 未来 Compose、备份脚本和启动命令没有对应实现，却未统一标记 `PLANNED`。

用户影响：操作者可能运行不存在或不适用于当前 checkout 的命令；验收状态可能被组织形式而非实际证据阻断。

处理：测试文档只保留分层策略；Runbook 只收录当前存在且跑过的命令；配置只引用 `.env.example`。

## 应删除或降级的限制

以下限制没有独立用户价值，应从产品合同降级：

- 固定表、API、错误码、任务和函数数量。
- 指定必须有几个 helper function、精确内部函数名或等价实现方式。
- 每个开发切片都生成 CR、snapshot、JCS/hash、九份文档原子同步或九角色签名。
- 把目录结构、任务估算、测试数量、离线 Gate 和当前授权状态写进长期需求。
- 在多份文档复制 DTO、状态枚举、`.env`、Prompt、Policy、AC 和错误码。
- 把远程分支保护、多人评审或生产环境证据作为本地 `implemented` 的必要条件。
- 用未批准候选 CR/DEP 自身声明阻断无关开发。

以下边界必须保留：

- PostgreSQL 是业务事实来源，MinIO 保存文件制品，Redis/Qdrant 只保存可恢复或派生状态。
- 前端只访问 Backend；Router 不直接访问数据库、Qdrant、MinIO 或模型。
- 长任务进入 Job/Worker；已发布版本不可原地覆盖。
- AI 不决定审批、权限、状态迁移或确定性财务规则，不伪造引用。
- 权限、职责分离、输入验证、日志脱敏、Trace、幂等、迁移原子性和可恢复性。
- 文档存在、代码实现、测试通过、运行成功和正式验收必须分开表述。

## 已落地结构

### 活跃叙述文档

| 文件 | 只负责 |
|---|---|
| `README.md` | 开发入口、优先级、SSOT、CR 触发条件和状态词典 |
| `PRODUCT_REQUIREMENTS.md` | 用户目标、范围、角色、核心流程、业务不变量、AC 和少量 NFR |
| `TECHNICAL_SPEC.md` | 架构边界、模块责任、机器事实来源和最小阻断 |
| `IMPLEMENTATION_PLAN.md` | 垂直切片、代码锚点、完成标准、最小验证和开放问题 |

UI、AI、测试和运维要求已按职责合入上述三份正文或指向机器事实源，不再各自复制 API、Schema、AC、配置和历史 Gate。

### 机器事实来源

- HTTP：FastAPI/Pydantic 生成的 OpenAPI。
- 数据库：Accepted Alembic head；ORM 和 PostgreSQL 集成测试做一致性校验。
- 枚举/错误码：Backend 统一 Registry，生成 OpenAPI/前端类型/契约测试。
- 状态机：一份机器可校验迁移表或代码定义。
- AI：版本化 JSON Schema、Prompt 和 Policy 制品。
- UI：Route manifest 与页面测试。
- 环境：实际 `.env.example` 与配置 Schema。
- 验收状态：追踪矩阵和实际证据，而不是散落的 prose 计数。

## 分阶段迁移

### 阶段 1：已完成

- 日常任务不再通读或同步九份文档。
- 旧九份文档降级为归档参考。
- 未批准 CR/DEP 不再自动成为前置。
- 简化 CR 触发条件和批准方式。
- 使用 [精简规格入口](requirements-map.md) 导航当前事实来源。

### 阶段 2：已完成

- 已把当前产品结果、安全边界和 AC 合并进干净基线，不再保留覆盖段。
- `decided_by` 和当前物理数据库由 accepted Alembic 事实确定；HTTP 由 OpenAPI 确定。
- 审核状态机、检索集规模、Qdrant 粒度、供应商和工作台数据源作为最小 `BLOCKED/OPEN QUESTION` 留在实施计划，不再污染无关切片。
- 错误码、枚举、状态、AI Policy 和配置由机器事实源及测试投影。

### 阶段 3：已完成

- 旧九份文档移入 `Request/archive/legacy-v1/`，移动前后 SHA-256 一致。
- 当前活跃身份由 `docs/request-manifest.md` 校验；旧身份继续由冻结的 `docs/baseline-manifest.md` 追溯。
- 根目录不再包含重复 API/表字段/AC/`.env`/Prompt/Policy 文档。

## 验收标准

规格简化完成时应满足：

- 任一字段、状态、错误码、环境值和验收阈值只有一个事实来源。
- 当前规则不依赖“顶部覆盖后文”的人工优先级计算。
- 实现一个已批准切片无需新增 CR 或同步九份文档。
- 未实现目标不会被表述为当前可运行合同。
- API、表和任务计数全部可自动生成，不再手写冻结。
- 需求、实现、验证和正式验收状态可独立查询。
- 安全、权限、数据完整性和可追溯边界没有因精简被降低。
