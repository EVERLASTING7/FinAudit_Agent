# CR-006-R1：操作审计日志完整性合同闭合

> 合同修订：`CR-006-R1`
> 文档属性：静态规范正文；实际审批、制品和实施状态只记录在第 9 节
> 事实日期：2026-08-07
> 适用范围：合同、数据库对象所有权、链证据 Schema 与联合审批输入；不授权 Request 同步、迁移、运行、网络或生产放行

## 1. 变更原因

`operation_logs` 是 AC-001、AC-015 以及权限拒绝、业务状态变更和恢复操作的追加写审计事实。当前 Request 已要求该表禁止 UPDATE/DELETE、按月分区并每日计算链式哈希，但仍不能唯一生成 PostgreSQL 16 Schema 和可重算的防篡改证据：

1. `result` 列给出了 `success/failure/denied` 枚举，却没有冻结是否允许 NULL。
2. `organization_id` 允许系统启动日志为空，但没有明确它是否仍是到 `organizations.id` 的可空外键及删除行为。
3. 单列 `UUID id` 主键与 `PARTITION BY RANGE (created_at)` 冲突：PostgreSQL 16 要求分区表的主键/唯一约束包含全部分区键。
4. 月分区的 UTC 边界、预创建窗口、默认分区、漏建分区和不可删除策略未冻结。
5. “每日计算分区链式哈希并写入备份清单”没有规范化字节、稳定排序、跨日锚点、重跑和恢复校验合同，无法证明不同实现可重算出同一结果。
6. `TBD-007` 尚未批准保留周期，迁移降级和分区维护不能据此推断可删除审计证据。

本 CR 只推荐关闭上述合同缺口。为让已封账日期在数据库内可强制拒写，推荐新增一张技术状态表 `operation_log_chain_state`。本 CR 的静态 delta 固定为 `api_path_delta=0`、`core_parent_table_delta=+1`；有效核心父表总数必须按第 4.2 节的动态 ledger 公式计算，禁止把任何历史锚点或条件结果写成永恒总数。本 CR 不批准 `TBD-007`，也不代表操作日志写入、OPS-004、备份恢复或 AC 已实现。本静态正文不因审批进展改变；是否可执行只由第 9 节和外部审批记录表达。

## 2. 推荐决策摘要

| 决策 | 推荐方案 |
|---|---|
| OPLOG-D-001 | `result` 固定为 NOT NULL 三态；`organization_id` 固定为可空、限制删除的组织外键 |
| OPLOG-D-002 | PostgreSQL 16 原生按 `created_at` 分区，主键改为 `(created_at, id)`，日志身份也固定为该二元组 |
| OPLOG-D-003 | 使用 UTC 月边界、滚动预建和只进不出的 fail-safe 默认分区；缺口告警但不搬移或删除审计行 |
| OPLOG-D-004 | 使用 `operation-log-chain-v1` 规范化行、稳定排序、跨 UTC 日 SHA-256 锚点和数据库可校验的封账水位 |
| OPLOG-D-005 | 受控写入与封账锁消除迟交事务；每日链清单与每次数据库备份清单分离且均不可覆盖 |
| OPLOG-D-006 | 含任一审计行的 downgrade 原子失败；`TBD-007` 获批前所有日志、分区和清单无限保留 |

## 3. 待审批推荐合同

### 3.1 OPLOG-D-001：结果与组织归属

- `result` 固定为 `VARCHAR(20) NOT NULL`，数据库 CHECK 只允许 `success/failure/denied`。写入方必须显式提供结果，不设置会掩盖漏写的默认值；未知值和 NULL 均 fail closed。
- `organization_id` 固定为 `UUID NULL REFERENCES organizations(id) ON UPDATE RESTRICT ON DELETE RESTRICT`。NULL 只允许下表三个已枚举的 system-global 动作，不泛化为“关闭”“基础设施事件”“未知组织”或租户过滤绕过；系统关闭等新动作必须先走 CR 并增加精确矩阵行。
- 组织级资源、用户动作和拒绝事件必须写非空 `organization_id`。系统级 NULL 组织事件必须同时满足 `actor_id IS NULL`，并严格匹配下表；数据库受控写入函数对 `action_code/resource_type/organization_id/actor_id` 联合校验，未知组合 fail closed。新增 system-global 动作必须走新 CR，不能仅发布代码或改环境变量。

| `action_code` | `organization_id` | `actor_id` | `resource_type` | 唯一生产者 |
|---|---|---|---|---|
| `system_startup` | NULL | NULL | `service` | Backend/Worker 启动探针 |
| `operation_log_partition_maintenance_failed` | NULL | NULL | `operation_log_partition` | 受限分区维护任务 |
| `operation_log_chain_failed` | NULL | NULL | `operation_log_chain` | 受限每日封账任务 |

`system_bootstrap` 必须在同一事务创建组织后写该组织 ID，`actor_id=NULL`、`resource_type='organization'`；它不是 NULL 组织动作。其他系统任务若已经有业务组织，也必须写非空组织，不得扩大上表。
- `actor_id` 非空时，受控数据库 wrapper 必须验证操作者与日志组织一致，并从 PostgreSQL 生成有效角色快照；该一致性不能通过省略 `organization_id` 或调用方自报角色绕过。操作日志外键均使用限制删除语义，任何账户或组织清理不得级联删除审计证据。
- `error_code` 仍是可空的固定安全错误码，不在本 CR 中扩展为自由文本。`reason` 和 `change_summary_json` 继续遵循现有脱敏要求；本决策不授权持久化凭据、正文、Provider 原始响应、异常或堆栈。

### 3.2 OPLOG-D-002：分区主键与稳定身份

首选合同固定为：

```sql
CREATE TABLE operation_logs (
  id UUID NOT NULL DEFAULT gen_random_uuid(),
  created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
  -- 其余列按批准后的字段合同定义
  PRIMARY KEY (created_at, id)
) PARTITION BY RANGE (created_at);
```

- `created_at` 是分区键的第一部分，`id` 是第二部分；单列 `id` 不再声明 PRIMARY KEY 或 UNIQUE。日志的数据库身份、Keyset 分页游标、导出清单和任何未来引用均固定为二元组 `(created_at, id)`。
- 本表是全局“`id UUID PRIMARY KEY`”规范的唯一已批准例外；同步 Request 时必须在通用主键规则和本表字段合同两处明确写出。`id` 仍由数据库生成用于显示和关联，但不具有脱离 `created_at` 的数据库唯一保证；禁止新增只携带 `operation_log_id` 的 API、外键、缓存键或导出引用。
- OPS-004 已同时返回 `id` 和 `created_at`，同步 Request 时应明确以 `(created_at DESC, id DESC)` 排序和翻页。未来若增加单条详情或外键，必须同时携带两列；不得把 `id` 单独描述为数据库唯一键。
- OPS-004 把现有 `page/page_size` 改为 `cursor/page_size`：`page_size` 默认 20、范围 `1..100`，`page` 与 `cursor` 同传或继续传 `page` 均返回 422。首屏在当前授权和规范化过滤条件下冻结最大可见 `(upper_created_at,upper_id)`，按 `(created_at DESC,id DESC)` 返回 `<= upper` 的记录；后续固定谓词为 `(created_at,id) < (after_created_at,after_id)` 且仍不得超过 upper。
- Cursor v1 使用 `base64url(payload_jcs_bytes) + '.' + base64url(HMAC-SHA256(key[kid], payload_jcs_bytes))`，两段都无 padding；验签覆盖整个 payload，不使用客户端可重算的无密钥 hash 充当防篡改。Payload 字段精确为 `v/kid/issued_at/expires_at/upper_created_at/upper_id/after_created_at/after_id/filters_hash`；时间使用 UTC 六位微秒，UUID 小写带连字符，TTL 固定 30 分钟。原始 cursor 最长 4096 字符、解码 payload 最长 2048 bytes；超限、base64/JCS/字段/类型/签名/时间/kid 错误均在使用翻页位置前返回 HTTP 400 `CURSOR_INVALID`，HMAC 使用常量时间比较。
- `filters_hash` 的唯一输入是 `operation-log-filters-v1` 对象经 JCS 后的 SHA-256。对象精确包含 `schema/requester_user_id/organization_id/effective_role_codes/data_scope_version/actor_id/action_code/resource_type/resource_id/result/trace_id/created_from/created_to`；所有键始终存在。`schema` 固定为 `operation-log-filters-v1`；`requester_user_id` 是后端从当前已认证主体取得的非空 UUID，调用方不能提交或覆盖，且与作为查询条件的 `actor_id` 是两个不同字段；其余 UUID 小写带连字符。角色去重后按 Unicode code point 升序；`data_scope_version` 是后端授权事实的非空版本标识；未提供的客户端过滤器一律编码为 JSON `null`，absent 与显式 null 不产生两种表示。`action_code/resource_type` 必须原样满足批准的小写 ASCII 注册值，前后空白、大小写折叠和 Unicode 等价替换一律 422，不做隐式规范化。时间统一为 UTC 六位微秒；区间固定为 `[created_from, created_to)`，两者非空且 `from >= to` 时 422。`page_size/cursor/upper/after` 不进入该对象。每页重新鉴权并以当前 requester 重算对象；合法签名但 requester、过滤器、组织、角色或数据范围版本变化返回 HTTP 409 `CURSOR_SCOPE_CHANGED`。HMAC 密钥只从 Secret Manager/受限 secret file 注入，日志与响应只暴露 `kid`；轮换时新签发只用 active key，previous key 至少保留 30 分钟后才能移除。响应 `pagination` 固定为 `page_size/next_cursor/has_more`，不返回会随追加写漂移的 total/page。
- 普通应用写入方不得直接 INSERT，也不得显式提供或修改 `id/created_at`；唯一写入口是 3.5 节受控函数。UUID 冲突但时间不同会形成两个不同的二元身份，不会造成主键歧义；查询、重试去重和证据链不得只用 UUID 定位记录。日志必须与所属业务写入/幂等记录/Outbox 在同一事务提交，未知提交结果只重放原业务幂等入口，禁止单独重放日志 INSERT。
- 当前 Request 没有表外键引用 `operation_logs.id`，因此复合主键本身不增加辅助业务表；本 CR 的 `core_parent_table_delta=+1` 只来自 3.4 的 `operation_log_chain_state`，不得把复合主键、物理分区或其他 CR 的 delta 重复计入。

不选择以下替代方案：

1. **保留单列 UUID 主键并暂不分区**：实现最简单，也保留 UUID 的数据库级全局唯一性，但不满足 P0 已要求的月分区与分区链完整性，只能作为本 CR 未获批准期间“不创建该表”的理由，不能作为最终实现。
2. **增加 UUID 注册表以维持跨分区全局唯一**：可让外部继续只引用 UUID，但会在封账状态表之外再增加第 59 张事实表、写入事务和恢复路径，没有当前引用需求，收益不足以覆盖复杂度。
3. **用触发器扫描所有分区或应用层先查后写保证 UUID 唯一**：并发、权限绕过、分区增长和恢复导入都使其难以可靠，不作为数据库唯一约束的替代品。
4. **以 UUID 派生月份分区**：PostgreSQL 16 不能从普通 UUID 稳定恢复 `created_at`，且会改变现有时间范围查询合同，因此不采用。

### 3.3 OPLOG-D-003：UTC 月分区和默认分区

- 父表使用 `RANGE (created_at)`；所有月分区边界均是 UTC 半开区间 `[YYYY-MM-01T00:00:00Z, next_month-01T00:00:00Z)`，命名固定为 `operation_logs_yYYYYmMM`。数据库 Session 时区不影响边界解释。
- 首次升级创建父表、当前 UTC 月、随后两个完整 UTC 月以及 `operation_logs_default`。受限部署调度任务每天 `00:05 UTC` 获取固定 advisory lock，设置 `lock_timeout='2s'`、`statement_timeout='30s'`，调用无参数的 `public.ensure_operation_log_partitions_v1()`，幂等确认“当前月 + 后两月”均已存在、边界正确且具有批准的索引、权限和不可变保护。该 system-global 调度不写 `async_jobs`、不伪造 organization/resource UUID，也不出现在 OPS-001；运行结果由独立结构化部署日志和 operation log 失败动作承载。
- `operation_logs_default` 是防止维护故障导致审计写入丢失的 fail-safe 分区，不是正常归档区。它必须具备与月分区相同的查询索引、禁止 UPDATE/DELETE/TRUNCATE 的权限和完整性校验。受控追加函数在 INSERT RETURNING 中检查实际 `tableoid`，返回 `landed_in_default`；若为 true，必须在同一数据库事务追加 `event_type='operation_log.default_partition_detected'`、`event_version=1`、`event_sequence=1` 的 Outbox 行。其 `aggregate_type='operation_log_alert'`，`aggregate_id` 固定为 UUIDv5 namespace `4f60becf-8807-53ae-98bd-5f710f9361de` 对 UTF-8 `created_at_utc_6_digits + '/' + lowercase_hyphenated_id` 的结果，`payload_json` 精确为 `{"created_at":"<UTC 六位微秒>","id":"<uuid>"}`。消费者按完整二元身份幂等发出外部结构化 `CRITICAL`；业务回滚时日志与告警事件一并回滚，提交后由 Outbox 保证可恢复投递。禁止 INSERT trigger 或消费者再次调用审计追加函数，避免递归。本条依赖获批并落地的 `CR-004` Outbox 合同。
- 默认分区中的行永不自动搬移、改写或删除。若某 UTC 月已有默认分区行，则不得为该月强行附加重叠范围分区；该月保持“默认分区承载”的完整性事件状态，记录缺口并采用经审批的前向修复。维护任务仍可为没有重叠默认行的后续月份继续预建分区。
- 调度任务遇到锁/语句超时、边界漂移或 default 重叠时不得阻塞审计写入或重试 DDL 风暴；本次调度失败退出并无条件输出一次固定结构化 `CRITICAL`。只有数据库可达、chain state 为 append-enabled、当前 UTC 日未封账、最终 action registry version/hash 匹配且专用 wrapper 可执行时，调度才额外尝试一次 `operation_log_partition_maintenance_failed`；任一条件不满足或该追加本身失败时只保留外部部署日志，不递归追加、不伪称 operation log 已持久化。如果该行落入 default，只使用函数返回的 `landed_in_default` 做外部去重告警。P0 不依赖尚未批准的 Prometheus、OPS-001 或 `/health/dependencies` 合同。
- 分区父表及维护函数由专用 `NOLOGIN` 角色 `finaudit_oplog_ddl_owner` 持有；广泛 migration owner 只在受控部署会话中 `SET ROLE`，其凭据不得进入日常调度容器。`public.ensure_operation_log_partitions_v1()` 是固定 `SECURITY DEFINER` 函数，不接收日期、表名、Schema、原始 SQL 或其他参数，只按数据库 UTC 当前月生成当前月与后两月的固定名称和半开边界，并且只能执行“验证既有分区”或“创建缺失未来分区”两类分支。函数体没有 DROP/DETACH/TRUNCATE/RENAME/任意 ATTACH 路径；遇到既有名称、边界、owner、索引、trigger 或权限不匹配即失败关闭。唯一调度登录角色固定为 `finaudit_oplog_partition_scheduler`，它只获得该函数和 `public.append_operation_log_partition_failure_v1(text,uuid)` 的 EXECUTE，不能 `SET ROLE`、不能取得 owner/migrator 凭据，也没有父表或子分区 DDL/DML权限；CR-008 的 producer role 必须逐字使用同一名称，不得使用 `finaudit_oplog_partition_maintainer` 别名。应用账号和日常审计查询账号同样无 DDL 权限。
- 默认分区行参与与其 `created_at` 对应 UTC 日的同一查询、排序、链式哈希、备份和恢复校验；不得因其物理位置不同而漏计。

### 3.4 OPLOG-D-004：`operation-log-chain-v1` 规范化与锚点

#### 3.4.1 行规范化

每一行先构造成 `schema="operation-log-row-v1"` 的 JSON 对象，固定包含 `operation_logs` 的全部业务列和身份列：`id/organization_id/actor_id/actor_role_codes/action_code/resource_type/resource_id/before_hash/after_hash/change_summary_json/reason/result/error_code/ip_address/user_agent/trace_id/correlation_id/created_at`。禁止只挑选“重要字段”。

规范化规则固定为：

- 使用 UTF-8 和 RFC 8785 JSON Canonicalization Scheme（JCS）；输入必须满足 I-JSON，不能规范化的值使本次任务失败并告警，禁止丢字段或字符串化兜底。
- `change_summary_json` 及其他 JSON 值中的 JSON number 递归只允许安全整数 `[-9007199254740991, 9007199254740991]`；非整数和超范围整数拒绝。数值负零按 PostgreSQL JSONB 的已存储语义规范化为整数 `0`，与输入 `0` 产生完全相同的规范化值和 hash，不把已经在 JSONB 边界丢失的词法形式作为数据库拒绝条件。普通 JSON string 始终按文本处理，例如编号 `"001"` 合法且不得被猜成数字。
- 精确 Decimal/超范围整数只能使用带类型对象 `{"$decimal":"<canonical>"}`；`$decimal` 为保留键，包含它的对象必须恰有这一键。canonical 值只允许正则 `^(?:0|-?(?:0\.[0-9]*[1-9]|[1-9][0-9]*(?:\.[0-9]*[1-9])?))$`，因此允许 `0`、`0.5`、`-0.01`、`10`、`10.01`，拒绝 `-0`、`00`、`001`、`1.0`、`+1` 和指数。这样类型由标签确定，哈希端不得根据字符串外观猜测或舍入。
- UUID 使用小写、带连字符形式；SHA-256 字段使用小写 64 位十六进制；NULL 使用 JSON `null`；布尔值使用 `true/false`。
- `created_at` 转为 UTC、六位小数的 `YYYY-MM-DDTHH:mm:ss.ffffffZ`；`ip_address` 使用 PostgreSQL `inet` 的规范地址文本，不附加默认掩码。
- `actor_role_codes` 必须在写入前去重并按 Unicode code point 升序保存，规范化时保留数据库中的实际数组；数组顺序、重复项或任一字符变化都必须改变行摘要。
- `change_summary_json` 作为 JSON 值参与 JCS，不先转换为自由文本。数据库受控写入函数调用递归校验器复核安全整数域和 `$decimal` 对象；Service 与 Worker/System producer 对解析后的 JSON 值执行相同语义校验，不依赖原始数值词法。哈希任务只规范化数据库已存储值，不得事后猜测或舍入。

行摘要和日链使用原始 digest bytes，不把十六进制文本误当原始字节：

```text
row_digest = SHA256(UTF8("operation-log-row-v1\n") || canonical_row_bytes)
chain_0    = previous_day_anchor_raw_32_bytes
chain_i    = SHA256(chain_(i-1) || row_digest_i)
day_anchor = SHA256(
  UTF8("operation-log-day-v1\n") ||
  UTF8(utc_date_YYYY-MM-DD) ||
  uint64_big_endian(row_count) ||
  chain_n
)
```

- 每个 UTC 日查询范围为 `[00:00:00Z, next day 00:00:00Z)`，把所有月分区和默认分区命中的行合并后按 `(created_at ASC, id ASC)` 唯一排序。
- 新增一个核心父表实体 `operation_log_chain_state` 作为写入屏障的数据库事实，只允许一行。精确列、类型和约束由第 4.3 节统一拥有；除原 chain/sealed 字段外，它必须持久化 `append_enabled`、`genesis_manifest_sha256`、`genesis_object_version_id`、`genesis_verified_at`、`restore_run_id`、`restore_transition_started_at`、`restore_operation_log_evidence_sha256`、`enablement_kind` 和 `enablement_completed_at`。`append_enabled=false` 时所有普通、Worker、Boot、维护和 sealer append wrapper 都必须在插入前 fail closed；只有新装 bootstrap wrapper 可在 genesis 已绑定、`enablement_kind` 尚为空的受控阶段执行。应用、Worker、查询和日常调度登录角色全部无直接 INSERT/UPDATE/DELETE/TRUNCATE；只有固定 owner 的初始化、genesis activation、初始 bootstrap completion、restore enablement、每日 sealer 和离线恢复 transition 函数可修改。所有路径都使用行锁和 `row_version` CAS，禁止跳日、回拨、DELETE、创建第二行或复用历史 chain ID。
- `chain_id` 是链初始化时生成的 UUIDv4，`chain_epoch_utc` 是该链开始的 UTC 日期。PostgreSQL 与 MinIO 不宣称跨系统 ACID；初始化固定为可重入 fail-closed saga：先在持有初始化 advisory lock 的数据库事务中创建 `append_enabled=false` 的状态行并提交，并原子写入 `transition_kind='fresh_genesis'` 以及全 null parent/source/restore tuple，其中 `restore_transition_started_at=null`；再只从该状态行持久化的 transition tuple 生成稳定 JCS genesis，以 no-replace 发布并 read-back 逐字节验证，禁止依赖进程内参数恢复；随后 `public.activate_operation_log_genesis_v1(uuid,bigint,char(64),text)` 在新事务中重新锁定同一 `chain_id/row_version`，原子写入 genesis hash/version 和数据库验证时间并保持普通 append 关闭；部署只临时允许 bootstrap wrapper，组织创建与 `system_bootstrap` 日志同事务成功后由 `public.complete_operation_log_bootstrap_v1(uuid,bigint)` 原子写 `enablement_kind='initial_bootstrap'`、数据库完成时间并开启普通 append。restore transition 必须在取得规定锁后由数据库 `clock_timestamp()` 一次性产生并与 DEP-005 `restore_run_id` 原子持久化 `restore_transition_started_at`，同时保持 evidence hash 为空；后续 genesis activation 与 restore completion 均不得修改该时间。`public.complete_operation_log_restore_v1(uuid,bigint,uuid,char(64))` 只接受同一 run，原子写 H 将复用的 `operation_log_chain_result.stage.evidence_sha256` 与 `enablement_kind='restore_transition'` 后才开启 append，不消费尚未生成的完整 H instance，也不得伪造 `system_bootstrap`。任一步崩溃都读取并比较已有状态/object 后从同一步重试，绝不生成新 chain ID、覆盖对象、重写 transition 起始时间、让另一 restore run 接管或提前开权限。新装空表 epoch 取初始化当日 UTC 日期。R1 migration 的 preflight 要求 `operation_logs` 尚不存在；若未来支持既有日志，必须新 CR 冻结停写、复制/校验和 backfill，不能由本 revision 猜测转换。任何向 active chain 新追加的日志行都不得早于 epoch；隔离恢复历史按 3.5.2 节处理。
- 所有每日锚点、差异记录和备份引用均以唯一权威键 `(chain_id, utc_date)` 标识；manifest/canonicalization 不兼容变更、重新升级或隔离恢复 transition 必须生成新 `chain_id`，不得在同一键下用 `schema_version` 制造第二身份。`fresh_genesis` epoch 日的 `previous_day_anchor_sha256` 是 64 个字符 `0`，其原始 seed 为 32 个零字节；`snapshot_tail_fork` 使用 `parent_tail_rows_sha256` 原始 32 bytes；`day_anchor_fork` 使用 `parent_day_anchor_sha256` 原始 32 bytes。此后以前一 UTC 日的 `day_anchor` 作为 `chain_0`，跨月不断链。
- 从 epoch 起每天都生成锚点；零行日也用 `row_count=0` 和 `chain_n=previous_day_anchor` 计算新锚点，以证明日期连续而不是静默缺日。
- 每日部署调度在 UTC `00:15` 之后把“昨日”只作为本轮可处理上界。每次启动先读取 append-enabled 的 `operation_log_chain_state`：若 `sealed_through_utc_date` 非空，必须先按其中的 `sealed_manifest_sha256` 验证该日权威对象；对象缺失时先幂等补发，内容不匹配时 fail closed，完成前不得选择新目标日。前置验证通过后，实际目标日固定为 `sealed_through_utc_date + 1 day`，尚未封过任何日期时为 `chain_epoch_utc`。目标日晚于昨日时正常退出，否则按 3.5 节封账协议取得该最早未封日的独占锁；绝不直接跳到昨日。取得锁后的下一条 READ COMMITTED 查询才建立可见性快照。计算出稳定 manifest bytes 后，sealer 在同一数据库事务内锁定 state，CAS 要求目标日仍恰好等于 epoch（首次）或当前 `sealed_through + 1 day`，然后写入目标日、日锚点 hash、manifest hash并递增 `row_version`；提交即永久拒绝该日及更早日期的新 append。MinIO 发布在提交之后；只有首次发布成功或既有对象逐字节匹配后才可处理下一日。发布失败保持“已提交待发布”，不能重新开放写入或跨日。任何失败无条件输出一次固定结构化 `CRITICAL`；仅当数据库、state、registry、当前日和 wrapper 条件均可达时，由直接登录的 `finaudit_oplog_chain_sealer` 额外尝试一次 `operation_log_chain_failed`，失败不递归且不改变外部告警事实。

### 3.5 OPLOG-D-005：受控写入、封账、清单和恢复

#### 3.5.1 受控写入与迟交事务屏障

- 父表、状态表及所有子分区对 `PUBLIC`、应用、Worker 和查询角色全部撤销直接 INSERT/UPDATE/DELETE/TRUNCATE。内部 owner 函数 `public.append_operation_log_v1(uuid,uuid,text,text,uuid,char(64),char(64),jsonb,text,text,text,inet,text,uuid,uuid)` 对任何登录角色都不授予 EXECUTE；只有第 4.3 节列出的七个固定 `SECURITY DEFINER` wrapper 可调用。`public` Schema actual owner逐字固定为`finaudit_oplog_ddl_owner`，且`REVOKE CREATE ON SCHEMA public FROM PUBLIC`是部署/IaC已批准并完成的两个external precondition；CR-006 migration只在任何DDL前验证owner等式与PUBLIC CREATE仍为false，绝不对`public`Schema或其他external object执行ALTER OWNER、REVOKE、GRANT或补偿。migration 只对本 revision 新建对象执行第 4.5 节 300 条 `revision_owned REVOKE ALL`，再执行 26 条精确 grant。DDL definer 与 runtime definer 分属不同 NOLOGIN owner；所有 definer 函数固定声明 `SET search_path = pg_catalog, public, pg_temp`，把 `pg_temp` 显式置于最后，且函数体内全部 relation/function/type/operator 仍完全限定。wrapper 使用 `session_user` 判定生产者；七个 producer 必须以表中角色直接认证，禁止共享 login 后 `SET ROLE`。调用方永远不能提供 `id/created_at/actor_role_codes`、registry version/hash 或 append-enabled 状态。

| `session_user` | 允许的动作域 | actor/组织规则 |
|---|---|---|
| `finaudit_app_rw` | 仅 CR-008 注册的业务/安全 action；禁止未注册值及 `system_*`、`operation_log_*`、`worker.*`；actor 为空只允许已知组织/目标用户的 `auth.login.failure/auth.login.denied/auth.account.lock/auth.token.revoke` | organization 必填；actor 非空时必须是同组织 active 用户；上述四个 actor-null action 固定使用 `resource_type='user'`、`resource_id=已知目标用户 UUID` |

| `finaudit_oplog_chain_sealer` | 仅 `operation_log_chain_failed` + `operation_log_chain` | organization/actor 为空 |

- wrapper 对 action/resource/producer 使用唯一获批 `operation-log-action-registry-v1` 的精确 allowlist，而不是只验证正则。批准包必须绑定 registry Schema raw hash、registry JCS hash、entry count、CR-004 Handler Registry version/hash/Schema hash，以及从同一 JCS 机械生成的 `operation-log-registry-sql-v1.sql` raw hash。该 SQL 只能把固定 rows/version/hash 编译进 `public.operation_log_registry_entry_v1(text,text,text,text)` 和 wrapper 常量，不新增 registry 表；调用方不得提交或选择 version/hash。Worker 四态 action 必须由已批准 Handler Registry 的精确 job_type 集合物化，数据库只消费已物化 action，不在运行时读取文件、环境变量或私有字典。任一 hash/版本/producer/job_type/矩阵不匹配均 fail closed。actor 非空时函数在数据库内验证 `public.users.organization_id/status/deleted_at`，并按事务时间从 `public.roles`、`public.user_roles` 与有效 break-glass 请求生成去重排序的 `actor_role_codes`；调用方不能提交或覆盖角色快照。CR-008 final artifact 及 Handler bundle 未批准并填入第 9 节前，migration 与 wrapper 保持阻塞。
- 缺失、畸形、过期或无法解析身份的 Token，以及无法关联现有组织/用户的登录失败，因不存在可验证的 `organization_id/actor_id`，P0 只写脱敏结构化安全日志并按 IP/设备摘要限流，不写伪造的 `operation_logs` 行；“所有拒绝访问写 operation_logs”在本 CR 中收窄为所有已识别组织和用户的 403/隐藏 404，以及注册表明确的已知目标登录拒绝。禁止用 NULL 组织或虚假用户填充 401；若未来要求数据库持久化 pre-auth 拒绝，必须另行批准精确全局 action、去重和隐私/DoS 边界。
- advisory lock domain 固定且互不复用：migration/restore topology lock=`680600000000000001`，partition maintenance lock=`680600000000000002`，chain initialization/activation lock=`680600000000000003`。每日锁只由 `public.operation_log_lock_key_v1(date) RETURNS bigint IMMUTABLE STRICT` 生成，精确算法为 `pg_catalog.hashtextextended('finaudit.operation-log.day.v1/' || pg_catalog.to_char(day,'YYYY-MM-DD'), 68060001::bigint)`；append 使用 `pg_advisory_xact_lock_shared`，sealer 使用 `pg_advisory_xact_lock`，两者都只调用该 helper，不依赖 Session `DateStyle`、时区或隐式转换。lock key 固定向量进入 CR-006 测试 bundle。
- append 使用循环消除“先取时间、后取锁”的跨日窗口：取 `candidate_day=UTC_DATE(pg_catalog.clock_timestamp())`，通过唯一 helper 取得该日共享事务锁，再重新取 `locked_at=pg_catalog.clock_timestamp()` 与 `locked_day`；只有二者相同才在同一快照读取唯一 `operation_log_chain_state` 行，并要求 `locked_day >= chain_epoch_utc` 且 `sealed_through_utc_date IS NULL OR locked_day > sealed_through_utc_date`，然后才以 `locked_at` 插入。稳定回拨到已封账日因此固定抛 `OPLOG_DAY_SEALED`，不会因候选日与锁后日相同而绕过。若锁前后日期变化，保留已取得的旧锁并以新日重试；连续三次仍不稳定则抛 `OPLOG_CLOCK_UNSTABLE`、不插入，并只发外部结构化告警。共享锁一直持有到调用方业务事务 COMMIT/ROLLBACK；sealer 推进水位前必须取得同一日独占锁，因此检查与推进不存在竞态。
- 封账使用专用非连接池会话，在 READ COMMITTED 事务中先通过同一 helper 取得目标日独占事务锁。该调用会等待所有已在锁后确定为目标日的事务提交或回滚；锁返回后的下一条查询才读取完整日范围。禁止在取得锁前建立 REPEATABLE READ 快照。
- `clock_timestamp()` 是本表相对通用 `DEFAULT now()` 的明确例外，因为事务开始时间不能代表实际审计事件插入时间。跨午夜且尚未取得旧日共享锁的调用最终归入锁后实际日；已经在旧日锁后确定时间并插入的事务持有旧日共享锁，封账必须等待。任何 privileged restore/COPY 必须离线停写并在放行前执行全链重算。

#### 3.5.2 每日链清单与不可覆盖发布

- 权威制品存储固定为 MinIO 专用 Bucket `audit-evidence`；配置名为 `MINIO_BUCKET_AUDIT_EVIDENCE`，文件系统只允许使用受限临时目录 staging，成功上传后清除，不是权威副本。Bucket 启用 versioning、服务端加密和独立只追加写/只读验证账号；日常应用账号无访问权，所有生产者无 overwrite/delete 权限。
- 对象键固定为：genesis `operation-log/v1/chains/{chain_id}/genesis.json`；每日权威清单 `operation-log/v1/chains/{chain_id}/days/YYYY/MM/YYYY-MM-DD/manifest.json`；验证事件 `operation-log/v1/chains/{chain_id}/verifications/YYYY-MM-DD/{verification_run_id}.json`；差异证据 `operation-log/v1/chains/{chain_id}/differences/YYYY-MM-DD/{difference_id}.json`；恢复 transition evidence `operation-log/v1/restores/{restore_run_id}/transition-evidence.json`；数据库备份制品与清单 `operation-log/v1/backups/postgresql/{database_backup_id}/database.dump.enc` 和 `operation-log/v1/backups/postgresql/{database_backup_id}/manifest.json`。所有写入使用 `If-None-Match: *` 或经过集成测试的等价 no-replace 条件，记录 object version ID；普通 PUT/rename 覆盖不合格。
- `operation_log_genesis_v1` 的 JCS 对象只允许七个键：`manifest_schema_version='operation-log-genesis-v1'`、`canonicalization_version='RFC8785-JCS'`、`hash_algorithm='SHA-256'`、`chain_id`（小写 UUIDv4）、`chain_epoch_utc`（`YYYY-MM-DD`）、`transition_kind` 和 `fork_parent`。`transition_kind` 只允许 `fresh_genesis/snapshot_tail_fork/day_anchor_fork`，并消费 DEP-005 C 的链事实与 G plan 的唯一矩阵；H 只做事后验证：
  - `fresh_genesis`：`fork_parent=null`。C `source_operation_log_row_count=0` 时 G target epoch 必须等于 `UTC-date(G.input_created_at)`，并且仅可在 `UTC-date(restore_transition_started_at)=target epoch` 时执行；row count 大于零时 target epoch 必须等于 `UTC-date(C.source_operation_log_first_log.created_at)`，允许该历史日期早于 transition 起始日。两种情况都由 restore controller 解析已验证 C 后选择，禁止从 state/plan 缺失的 row count 猜测分支。
  - `snapshot_tail_fork`：`fork_parent` 精确六键 `parent_kind='snapshot_tail'/parent_chain_id/parent_snapshot_txid_snapshot_sha256/parent_tail_rows_sha256/source_database_backup_id/source_database_manifest_sha256`；day/date anchor 字段不存在。target epoch 必须等于 `UTC-date(G.input_created_at)`，并且 restore 执行时还必须等于 `UTC-date(restore_transition_started_at)`；首日 `chain_0` 使用 `parent_tail_rows_sha256` 的原始 32 bytes。
  - `day_anchor_fork`：`fork_parent` 精确六键 `parent_kind='day_anchor'/parent_chain_id/parent_utc_date/parent_day_anchor_sha256/source_database_backup_id/source_database_manifest_sha256`。G target epoch 必须等于 `parent_utc_date + 1 day`，只验证该 plan epoch 关系，不要求等于 `UTC-date(restore_transition_started_at)`；首日 `chain_0` 使用 parent day anchor 原始 32 bytes。
  backup ID 为小写 UUIDv4，所有 hash 为 64 位小写十六进制。不得加入生成时间、运行 ID、主机名或可漂移数组；相同 state/transition 输入永远生成相同 bytes。source manifest ref、chain manifest ref 和 object version 由 DEP-005 C/G/H 在 genesis 外绑定，禁止为了方便向稳定 genesis 加入可漂移存储位置。
- 一个 UTC 日唯一权威键是 `(chain_id, utc_date)`，与上面的唯一 manifest key 一一对应。`audit_chain_manifest_v1` 的 JCS 对象精确包含：`manifest_schema_version='audit-chain-manifest-v1'`、`canonicalization_version='RFC8785-JCS'`、`row_schema_version='operation-log-row-v1'`、`hash_algorithm='SHA-256'`、`chain_id/chain_epoch_utc/utc_date/range_start/range_end/partitions/row_count/first_log/last_log/previous_day_anchor_sha256/day_anchor_sha256`。日期和 UUID 按 genesis 规则；范围时间为 UTC 六位微秒；`row_count` 为非负安全整数；非空日的 `first_log/last_log` 都是只含 `created_at/id` 的对象，空日二者均为 null。`partitions` 是目标日局部的固定物理集合：只包含边界与 `[range_start,range_end)` 相交的 range 分区，并始终把 default 分区恰好列一次；不相交的历史或预建未来分区一律不进入。元素只含 `partition_name/partition_kind/lower_bound/upper_bound`；range 分区使用真实 UTC 半开边界，default 分区的两边界均为 null。数组先列 range，按 `(lower_bound,upper_bound,partition_name)` Unicode code point 升序，再把 default 固定放最后；不得依赖 catalog 返回顺序。权威清单不得包含 `alembic_revision`、`application_version`、run ID、生成时间或其他会随部署/运行变化的值。
- 首次发布和同日重跑都先生成上述稳定 JCS bytes。目标已存在时只读出并逐字节比较，绝不覆盖。相同则 no-replace 追加 `audit_chain_verification_event_v1`，其 JCS object 精确十二键：`event_schema_version='audit-chain-verification-event-v1'`、`canonicalization_version='RFC8785-JCS'`、`hash_algorithm='SHA-256'`、`verification_run_id`、`generated_at`、`chain_id`、`utc_date`、`outcome='matched'`、`manifest_sha256`、`object_version_id`、`alembic_revision`、`application_version`。不同则保留原锚点，no-replace 追加 `audit_chain_difference_v1`，其 JCS object 精确十六键：`difference_schema_version='audit-chain-difference-v1'`、`canonicalization_version='RFC8785-JCS'`、`hash_algorithm='SHA-256'`、`difference_id`、`verification_run_id`、`generated_at`、`chain_id`、`utc_date`、`original_manifest_sha256`、`recomputed_manifest_sha256`、`original_day_anchor_sha256`、`recomputed_day_anchor_sha256`、`original_row_count`、`recomputed_row_count`、`original_object_version_id`、`safe_reason_code='MANIFEST_BYTES_MISMATCH'`，并触发 Critical。UUID/time/hash/count 均用第 4.5 节共同类型；两个运行制品的对象 key 含各自 UUID，因此重试先 read/compare，不覆盖。部署升级、未来分区预创建或索引变化后重跑同一已封日仍必须得到相同权威 manifest bytes；任何 rename/repartition/attach/detach 若会改变已封日 `partitions` 数组均禁止。Schema 或 canonicalization 不兼容升级必须新建 chain_id。
- PostgreSQL 导出、加密和恢复 Profile 不由 CR-006 复制定义。CR-006 只消费 DEP-005 A `database-backup-profile-v1`、B `backup-encryption-profile-v1`、C `database-backup-manifest-v1`、D inventory、F policy、G restore input 和 H pre-traffic verification 的 approved-artifact version/hash。A 必须选择 `pg_dump_custom`、`serializable_read_only_deferrable` 和导出 snapshot；`observed_wal_lsn` 永远只是诊断值。CR-006 拥有的 `operation-log-row-v1` 与 tail hash 固定向量必须由 A 的 `operation_log_tail_hash_version` 精确引用，版本/hash 不匹配即拒绝备份或恢复。
- C 的 `chain_snapshot.source_chain_mode` 只允许 `chain_absent/initialized_unsealed/sealed`，并按 DEP-005 精确绑定 source genesis、snapshot TXID hash、最后 verified anchor 和 `unsealed_tail.tail_rows_sha256`。CR-006 verifier 必须在同一导出 snapshot 内重算 row digest、连续锚点和 tail hash；不得以 WAL、墙钟、清单存在或对象 key 猜测一致性。C/G/H 的 source backup ID、manifest hash、snapshot/tail hash 与第 3.5.2 节 genesis union 必须逐字一致。

### 3.6 OPLOG-D-006：降级和无限保留

- 任何删除父表、月分区、默认分区、`operation_log_chain_state`、不可变触发器或链式哈希依赖对象的 downgrade，必须在同一事务依次取得固定 migration advisory lock、`LOCK TABLE operation_logs IN ACCESS EXCLUSIVE MODE`（覆盖父表与全部后代写入）和 `LOCK TABLE operation_log_chain_state IN ACCESS EXCLUSIVE MODE`，校验分区拓扑，再检查全部分区。只要存在一条日志，或状态行已存在/已初始化，立即抛错并在任何 DDL 前原子停止；禁止 `CASCADE`、`TRUNCATE`、自动导出后删除或绕过检查。
- 仅当父表及全部分区为空且状态表从未初始化时，downgrade 才可删除 symbolic owner `cr006_r1_operation_log_integrity` 自己创建并由外部 migration object manifest 精确绑定的表、分区、函数、触发器和索引；不得删除先前 revision 的组织、用户、扩展、角色或其他业务对象。精确对象和逆序见第 4.6 节。
- 外部 genesis、每日链、验证、差异和备份清单即使对应空日志日也不得由 downgrade 删除；降级前由部署流程只读检查 MinIO 对象键、chain_id 与 no-replace 权限，失败即不启动 Alembic。这是外部前置门禁，不宣称与数据库 DDL 跨系统原子。
- 空表 downgrade 后重新升级必须创建新的 `chain_id`；旧制品继续保留在旧命名空间。任何已存在业务日志或无法区分 chain_id 的旧清单都使部署前置门禁失败，而不是由 Alembic 猜测、删除或覆盖旧链；数据库 downgrade 本身只在锁内依据 PostgreSQL 拓扑和行事实决定是否执行。
- `TBD-007` 及部署侧等价保留期未获正式批准前，`operation_logs`、月分区、默认分区、链锚点、差异记录和备份清单一律按无限期保留处理。自动任务不得 DROP/DETACH/TRUNCATE/DELETE/归档后清理，磁盘压力、Docker 日志轮转或备份成功均不构成删除授权。
- 容量门禁采用监控、扩容和提前告警，不以删除审计证据止损。未来保留期审批必须另行说明法律/业务依据、最短期限、legal hold、双人审批、清理清单、链锚点闭合、备份同步和可恢复回滚；本 CR 不预先批准其中任何数值或清理行为。

## 4. Migration 所有权、动态 ledger 与机器制品

### 4.1 唯一 revision 和 preflight

本合同只允许一个线性 Alembic revision 拥有全部 CR-006 数据库对象；静态正文只冻结不可变 symbolic owner，不预占日期序号、文件名或当时的 Alembic head：

| 字段 | 合同值 / 绑定规则 |
|---|---|
| symbolic owner | `cr006_r1_operation_log_integrity` |
| actual migration file | 由外部 `cr006-migration-object-manifest-v1` 在联合审批前绑定真实仓库相对路径 |
| actual `revision` | 由同一 manifest 在联合审批前绑定唯一真实值 |
| actual `down_revision` | 全部获批上游 migration 已落入同一线性链后，当时唯一 Alembic head 的真实值 |
| migration advisory lock | `680600000000000001` |

创建 migration 前必须在同一 checkout 先完成 CR-003/004/005/007/009/010 及 DEP-005/CR-008 所需 migration 的批准、分配与线性落链，再证明仓库和目标数据库各自恰有且指向同一唯一 head。随后把 actual file、`revision`、`down_revision` 和完整对象清单写入外部 `cr006-migration-object-manifest-v1`，由 CR-006/008 联合审批绑定；目标 revision/file 尚不存在，`public.operation_logs`、`public.operation_log_chain_state` 及本节全部命名对象均不存在，且没有同名临时、非 `public` 或错误 owner 对象。绑定后若 head、文件或任一对象事实漂移，必须停止并提升 CR revision、重新生成 snapshot 与审批包；不得自动改 `down_revision`、建立 merge revision、接管既有对象或沿用旧签名。R1 只支持首次创建；已存在未分区/分区 `operation_logs` 的数据库必须 fail closed，既有数据转换另行 CR。

### 4.2 动态 delta ledger

本 CR 固定贡献：`api_path_delta=0`、`core_parent_table_delta=+1`、`owned_alembic_revision_count=1`。`operation_logs` 已在 baseline 核心父表集合中，新增核心父表只有 `operation_log_chain_state`；月/default 分区、索引、trigger、function、role 和外部 artifact 都不是核心父表。action registry 行由 CR-008 的唯一 artifact/ledger 拥有，CR-006 不重复申报一个 action 总数。

任一时点的有效核心父表总数必须机械计算为：

```text
effective_core_parent_table_total =
  core_parent_table_count(parsed from the exact synced baseline_manifest_sha256)
  + sum(core_parent_table_delta of every approved CR not yet synced into that baseline)
```

同一 delta 一旦进入新 baseline 就从未同步 ledger 移除，禁止二次累加。任何具体总数只能作为第 9 节的可重算状态证据；第 1—8 节不冻结最终总数。

所有上述 state CAS 函数都先按 `p_chain_id`（transition 为 `p_expected_current_chain_id`）锁定唯一 state，再精确比较 `p_expected_row_version`；除 fresh restore 分支规定的 null 外，任一 expected 参数为 null 或不匹配都失败且不改行。initialize 只允许 state 不存在、空父表和数据库 UTC 当日 epoch，并固定创建 fresh/null parent/null source tuple及 `restore_transition_started_at=null`。activate 只接受当前持久化 transition tuple 生成、已 no-replace/read-back 的 genesis hash/version且不得修改 `restore_transition_started_at`；bootstrap completion 只接受 fresh/null source tuple、该时间仍为 null和已落库的 `system_bootstrap` 事务事实；sealer 要求 `p_utc_date` 是 epoch 或 sealed-through 的严格下一日，两个 hash 与本轮稳定 bytes 一致。

`public.transition_operation_log_chain_v1` 的参数顺序以上表为唯一规范，所有分支都要求 `p_restore_run_id` 为本次 G 的 UUIDv4 且未被不同 transition 使用。函数在已持有规定 advisory/table/state locks 后取一次数据库 `pg_catalog.clock_timestamp()`；该值不是参数，也没有客户端回退源。三分支 null/派生规则固定为：`fresh_genesis` 要求 `p_expected_current_chain_id/p_expected_row_version` 和五个 parent 参数全 null，source pair 全 non-null且 state 不存在；在同一锁定快照内恢复后 `operation_logs` 零行时，要求 `p_target_chain_epoch_utc=UTC-date(restore_transition_started_at)`，非零行时改为要求 `p_target_chain_epoch_utc=UTC-date(按 (created_at,id) 升序首行.created_at)` 且不比较 transition 时钟日期。`snapshot_tail_fork` 要求 expected current tuple non-null且匹配，`p_parent_chain_id=p_expected_current_chain_id`，parent date/day anchor 为 null，snapshot TXID/tail/source pair 全 non-null，且 `p_target_chain_epoch_utc=UTC-date(restore_transition_started_at)`；`day_anchor_fork` 同样要求 expected tuple匹配且 parent chain 相等，parent date/day anchor/source pair 全 non-null，snapshot/tail 全 null，target epoch 必须等于 parent date 加一日且不与 transition 时钟日期比较。只有 `snapshot_tail_fork` 或已由 restore controller 解析 C 并由锁内数据库事实确认为零行的 `fresh_genesis`，G target epoch 与锁后日期不同才视为跨日 stale G，并在任何 state 写入前 fail closed；fresh 非零行允许历史 epoch。禁止函数改写 epoch 或代替调用方生成新 G。所有分支的 target chain 必须是未用过的 UUIDv4；函数把 run owner、锁后 `restore_transition_started_at` 与批准字段原子写入第 4.3 节 state/transition tuple，调用方不能省略、交换或从另一分支借用字段。同 run 已有精确 state 的重入只核对并返回已持久化值，不得刷新该时间。

`public.complete_operation_log_restore_v1` 只在 chain/genesis 已验证、补链完成、state 仍 append-disabled、`p_restore_run_id` 精确等于 transition 时已持久化的 run owner、`restore_transition_started_at` non-null 且 evidence 字段仍为空时接受专用 restore controller 调用，并在同一行锁/CAS 事务只写入已读回验证的 `p_restore_operation_log_evidence_sha256`，不得修改已持久化的 transition 起始时间；evidence 内该时间必须逐字等于 state，before row version 必须等于 `p_expected_row_version`、expected after 必须等于函数返回值。重跑只能提交同一 run/hash/time，另一 run 不得接管。它不接收完整 H instance ref；最终 H 必须在同一 restore run 下逐字复用该 evidence hash，差异由 DEP-005 companion validator 拒绝。

所有非 trigger runtime 函数为 `SECURITY DEFINER VOLATILE`，lock helper 为 `IMMUTABLE STRICT SECURITY INVOKER`，mutation function 为 `SECURITY INVOKER`，ensure 为 DDL owner 的 `SECURITY DEFINER VOLATILE`。所有函数 `SET search_path=pg_catalog,public,pg_temp` 且 body 完全限定；无动态 SQL，唯一例外是 ensure 按已验证固定模板用 `format('%I', generated_name)` 创建未来分区，模板之外输入不可达。

角色及对既有对象的权限由部署/IaC 在 CR-006 migration 之外预置并单独批准；Alembic 只验证其精确属性、membership 和 external-precondition ACL，upgrade/downgrade 均不 CREATE/DROP role，也不 GRANT/REVOKE 既有 schema、Outbox、organization、user、role 或其他上游对象。本 revision 的 ACL role allowlist 恰为十三个：`finaudit_oplog_ddl_owner`、`finaudit_oplog_runtime_owner`、`finaudit_migrator`、`finaudit_app_rw`、`finaudit_worker_rw`、`finaudit_bootstrap`、`finaudit_backend_boot`、`finaudit_worker_boot`、`finaudit_oplog_partition_scheduler`、`finaudit_oplog_chain_sealer`、`finaudit_restore_controller`、`finaudit_backup_ro`、`finaudit_audit_ro`；该有序集合记为 `R13`。前两个 owner 必须 `NOLOGIN NOINHERIT NOBYPASSRLS`；其余十一个角色必须 `LOGIN NOINHERIT NOBYPASSRLS`，且全部十三个角色都必须 `NOCREATEDB NOCREATEROLE NOREPLICATION NOSUPERUSER`。PostgreSQL 16 membership 边界查询必须读取所有满足 `roleid IN R13 OR member IN R13` 的 `pg_auth_members` row，结果恰为两条 direct edge：member=`finaudit_migrator` 分别指向 granted role=`finaudit_oplog_ddl_owner/finaudit_oplog_runtime_owner`，两条都固定 `admin_option=false/inherit_option=false/set_option=true`；这既捕获任一 R13 角色被加入外部 role 的出边，也捕获外部 member 被加入 R13 role 的入边，而不误拒与 R13 无关的 external-to-external membership。该边界使 migrator 只能在受控会话显式 `SET ROLE`，不能自动继承、转授权或把 owner 权限传给第三者；七个 producer、restore controller和两个只读角色均不得成为两个 owner 的 direct/indirect member。

ACL 分成两个不混写的 ownership scope。`external_precondition` 要求部署/IaC 已单独执行并批准：`public` Schema actual owner逐字为`finaudit_oplog_ddl_owner`，`PUBLIC`保留`USAGE`但已撤销`CREATE`；runtime owner 对既有 `public.outbox_events` 仅有 `INSERT`，对既有 `public.organizations/public.users/public.roles/public.user_roles/public.break_glass_requests` 仅有 `SELECT`。Schema owner等式是独立catalog precondition，不新增ACL manifest row；CR-006 migration只在任何DDL前验证owner与八条ACL事实，缺失或额外即失败，绝不修改，downgrade也不“恢复”或撤销。`revision_owned` 只覆盖本 revision 新建的两表、四个初始分区和十九个函数：创建后从 PUBLIC/全部十一个登录角色 REVOKE ALL，再仅按上表 GRANT wrapper/function EXECUTE；`finaudit_app_rw` 与 `finaudit_audit_ro` 获 `operation_logs` SELECT，`finaudit_oplog_chain_sealer` 与 `finaudit_backup_ro` 获两表 SELECT，runtime owner 只获本 revision append/state 所需 SELECT/INSERT/UPDATE，其他 producer 无表权限。downgrade 通过 DROP owned object 消除这些 ACL，不对任何外部对象发 GRANT/REVOKE。任何直接 child DML、TRUNCATE、DDL、owner membership 或未列 EXECUTE 都必须被拒绝。第 4.5 节的 manifest 生成矩阵是上述 ACL 的唯一机器表示；自然语言不得增加第二套 ACL 行。

每个非`op.execute`的`alembic_dsl`call必须由上述exact compiler binding在offline mode编译成最终PostgreSQL raw SQL：每个emitted construct保持compiler原字符序列，多construct按emission order以单个ASCII`semicolon+LF`连接且无额外trailing delimiter；结果必须是无BOM UTF-8/LF、无bind parameter/placeholder的非空bytes。`op.execute`只接受单个literal string，其raw bytes同样必须无BOM UTF-8/LF且禁止bind parameter。所有statement的`sql_sha256`均为non-null Sha256并逐字等于其最终raw SQL bytes；DSL不得再使用null或只hash AST fragment。每份raw SQL都由绑定的PostgreSQL 16 server parser完整切分，零base command、parse warning、trailing未消费bytes或compiler/SQL hash漂移均在数据库连接前拒绝。base command精确三键`base_ordinal/command_tag/expected_event_set`，base ordinal从1连续；session command只允许tag=`SET`且event set=`[]`，DDL tag使用下述allowlist且event set非空。event-set不是statement或base-command的一对一row：它是`pg_event_trigger_ddl_commands()`返回base rows的规范multiset，元素精确五键`command_tag/object_type/schema_name/object_identity/multiplicity`，前四项均为non-null string且`object_type`enum顺序固定为`schema/table/table constraint/index/function/trigger`，multiplicity为正integer；先按前四字段Unicode code point排序并合并相同tuple。

`object_counts` 精确十二键：`relation_count/parent_table_count/initial_partition_count/constraint_count/parent_state_index_count/initial_child_index_count/trigger_instance_count/function_count/wrapper_function_count/role_requirement_count/acl_rule_count/object_entry_count`，固定值依次为 `6/2/4/21/8/24/10/19/7/13/334/435`；增加 catalog 验证字段不增加 object，故 `object_entry_count=objects.length=101+334=435` 保持不变。`objects[]` 是封闭 `oneOf`，每个 variant 均 `additionalProperties=false` 且所有键 required：relation=`kind/identity/relation_kind/owner/persistence/tablespace_identity/parent_identity/partition_bound/columns`；constraint=`kind/identity/relation_identity/constraint_kind/column_or_expression_signature`；index=`kind/identity/relation_identity/index_kind/key_signature/attached_parent_identity`；trigger=`kind/identity/relation_identity/timing/event_set/level/function_signature/parent_managed/enabled_mode/tgtype/update_column_attnums/parent_trigger_identity/condition_sql/arguments`；function=`kind/identity/return_signature/owner/language/security/volatility/strictness/parallel_safety/search_path/body_source/body_source_sha256/direct_caller_roles`；role_requirement=`kind/identity/required_attributes/forbidden_attributes/membership_mode/member_roles/admin_option/inherit_option/set_option`；acl_rule=`kind/identity/object_identity/grantee/privilege/effect/ownership_scope`。

“PostgreSQL 16 controlled catalog projection”只允许以下唯一算法，不允许实现自选`pg_dump`、ORM reflection、pretty printer或等价SQL，也不表示覆盖范围外catalog。验证事务先固定`server_version_num`属于`160000..169999`、`client_encoding='UTF8'`、`TimeZone='UTC'`、`DateStyle='ISO, YMD'`、`IntervalStyle='postgres'`、`standard_conforming_strings=on`和`search_path=pg_catalog,public,pg_temp`，然后执行：

1. 本节只定义 `controlled catalog projection`，不声称枚举全部 PostgreSQL对象或发现范围外catalog变化。验证事务在任何migration语句前和upgrade完成后各投影一次封闭target closure：`pg_namespace`只含actual owner逐字为`finaudit_oplog_ddl_owner`的`public`；`pg_class`只含六个external-precondition relation、38个revision-owned relation/index；`pg_proc`只含十九个revision function；`pg_constraint`只含`public.organizations.pk_organizations/public.users.pk_users`、二十一root及其递归derived closure；`pg_trigger`只含十个revision non-internal trigger和第5步二十四个RI internal trigger。pre projection必须只有上述`public`、六个external relation和两个external PK，所有reserved revision identity均不存在；post projection必须恰增加上述revision-owned/直接依赖集合且namespace item逐字不变。两个专用owner在`public`的class/proc全集仍作额外subset门禁，DDL前均为空，DDL后class为38/0、proc为2/17。范围外显式DDL只能由第4.5节closed AST/SQL inventory与受保护event-trigger ledger发现；PostgreSQL派生internal对象只由本projection的constraint/RI规则验证。三证必须合取，任何单证都不能宣称“无额外DDL”。

   controlled snapshot根精确五数组`namespaces/classes/procedures/constraints/triggers`，数组按该顺序、各自按下述stable identity Unicode code point升序且唯一，不使用fingerprint wrapper。共同`AclAtom`精确四键`grantor/grantee/privilege/is_grantable`，前三项string、末项boolean。namespace、relation、function分别唯一使用`aclexplode(COALESCE(nspacl,acldefault('n',nspowner)))`、`aclexplode(COALESCE(relacl,acldefault('r',relowner)))`、`aclexplode(COALESCE(proacl,acldefault('f',proowner)))`；index不具有独立ACL且固定`acl_atoms=[]`。null ACL必须使用相应`acldefault`，non-null ACL只展开自身，禁止混用object class或把null当空集。grantor/grantee OID必须在同一snapshot解析唯一`pg_roles.rolname`，只有grantee OID 0映射literal`PUBLIC`，grantor 0、缺失role或重复映射均拒绝。privilege enum按object class分别固定为namespace=`USAGE/CREATE`、relation=`SELECT/INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER`、function=`EXECUTE`、index=`[]`；未知privilege拒绝，`is_grantable`只允许boolean。atom按`(grantor,grantee,privilege enum ordinal,is_grantable false<true)`排序且四键tuple唯一；actual-owner atoms在snapshot中完整保留，只能在后续effective ACL等式比较时按本文规则排除。共同`DependencyEdge`精确三键`referenced_kind/referenced_identity/dependency_type`，kind enum为`class/procedure/constraint/trigger/type/operator/collation/access_method`，dependency type enum为`n/a/i/P/S`，按三字段排序且唯一。任一其他OID必须在同一事务解析：namespace/class=`quote_ident(nspname)||'.'||quote_ident(name)`；procedure=`quote_ident(nspname)||'.'||quote_ident(proname)||'('||pg_get_function_identity_arguments(oid)||')'`；constraint=`relation_identity||'.'||quote_ident(conname)`；type/collation分别为`quote_ident(nspname)||'.'||quote_ident(typname或collname)`；operator为`quote_ident(nspname)||'.'||quote_ident(oprname)||'('||format_type(oprleft,NULL)||','||format_type(oprright,NULL)||')'`且本closure只允许两端type OID均非0；access method为无namespace的`quote_ident(amname)`。attnum vector保留正integer数组，operator OID vector逐项转上述stable identity。禁止在JCS中保存OID、OID vector、relfilenode、统计值、事务ID、真实含OID的internal trigger name或未定义的`ACL/options/dependencies`自由对象。

   namespace item精确四键`kind='namespace'/identity='public'/owner='finaudit_oplog_ddl_owner'/acl_atoms`，pre/post四键JCS必须逐字相等。class item精确十四键`kind='class'/identity/projection_role/class_kind/relkind/owner/persistence/tablespace_identity/is_partition/parent_identities/partition_bound_sql/projected_columns/definition_sql/acl_atoms`：projection role enum为`revision_owned/external_precondition`，class kind为`relation/index`，relkind为`r/p/i/I`，persistence固定`p`；tablespace OID 0映射null，否则映射tablespace name string；parent数组排序唯一。relation的definition固定null，index的definition逐字为`pg_get_indexdef(oid,0,false)`、projected columns与acl atoms都固定`[]`。revision relation的projected columns使用manifest七键column shape并全量投影；external只对organizations/users投影唯一`id`列，其余四表为`[]`。partition bound只对四个partition non-null并使用`pg_get_expr(...,false)`；其他为null。六个external relation均要求`relkind='r'/is_partition=false`且owner不是runtime owner，revision classes的owner/tablespace/parent/bound/ACL按manifest逐项相等。没有sequence进入target closure，`CREATE/ALTER SEQUENCE`由statement inventory拒绝，因此不存在sequence definition的string/object二义性。

   procedure item精确十五键`kind='procedure'/identity/return_signature/owner/language/security/volatility/strictness/parallel_safety/search_path/body_source/body_source_sha256/direct_caller_roles/definition_sql/acl_atoms`，类型及enum沿用manifest function variant，definition逐字为`pg_get_functiondef(oid)`，所有array排序唯一。通用stable identity始终使用真实namespace；本closure十九项另外要求`nspname='public'`，不得用`public.`硬编码去投影范围外procedure。constraint item精确十四键`kind='constraint'/semantic_identity/projection_role/relation_identity/parent_constraint_identity/contype/definition_sql/backing_index_identity/referenced_relation_identity/conkey_attnums/confkey_attnums/operator_identities/flags/dependency_edges`；projection role enum为`external_key/root/derived`，contype enum为`p/u/f/c`。`operator_identities`精确三键`pfeq/ppeq/ffeq`且各为排序array；`flags`精确九键`validated/deferrable/deferred/is_local/inheritance_count/no_inherit/update_action/delete_action/match_type`，前三项及is_local/no_inherit为boolean、inheritance count为非负integer，三个action字段仅FK为non-null单字符enum、其他constraint固定null。parent identity仅derived non-null；referenced identity/confkey/operator arrays仅FK non-null/non-empty；backing index仅p/u/f non-null；definition固定`pg_get_constraintdef(oid,false)`。trigger数组是封闭oneOf：non-internal item精确十四键`kind='noninternal_trigger'/semantic_identity/relation_identity/timing/event_set/level/function_identity/parent_managed/enabled_mode/tgtype/update_column_attnums/parent_semantic_identity/condition_sql/arguments`并逐项等于manifest trigger；RI item严格使用第5步十七键shape。所有nullable、array排序与空数组均由这些item matrix决定，不存在其他内层shape。

   `pre_controlled_catalog_sha256/post_controlled_catalog_sha256`分别为上述exact snapshot JCS bytes的SHA-256。`controlled_catalog_delta`精确四键`added_identities/removed_identities/modified_identities/addition_counts`，前三项为按`namespace/class/procedure/constraint/noninternal_trigger/ri_trigger`后semantic identity排序的唯一string数组；modified由同identity item JCS bytes不等产生。removed/modified和namespace added必须均为`[]`；added恰为38 class、19 procedure、21 root constraint、运行时derived constraint、10 non-internal trigger及24 RI trigger。addition counts精确七键`namespace_added/class_added/procedure_added/root_constraint_added/derived_constraint_added/noninternal_trigger_added/ri_internal_trigger_added`，值依次为`0/38/19/21/derived_constraint_facts.length/10/24`。external facts pre/post逐字相等。该delta只证明target closure；是否存在其他显式DDL必须由批准inventory与event ledger另证。
2. relation/column rows 从 `pg_catalog.pg_class c JOIN pg_catalog.pg_namespace n` 读取 manifest 六个 relation identity且只允许 `n.nspname='public'`；不得先按期望计数截断。六项都要求 `c.relpersistence='p'`、`c.reltablespace=0`，映射为 manifest `permanent/null`。`c.relkind='p' AND NOT c.relispartition` 映射 `partitioned_parent`，`c.relkind='r' AND NOT c.relispartition` 映射 `ordinary_table`，`c.relkind='r' AND c.relispartition` 必须经 `pg_catalog.pg_inherits` 恰好一条 parent edge 指向 `public.operation_logs`；其他 relkind、零/多 parent 或其他 parent 一律拒绝。`pg_catalog.pg_get_expr(c.relpartbound,c.oid,false)` 对两个 parent 必须为 null、对 default 必须逐字为 `DEFAULT`。range 的 manifest `from_utc/to_utc` 必须先独立验证为 `YYYY-MM-01T00:00:00.000000Z` 与严格下一月；令 `F=from_utc[0:10]`、`T=to_utc[0:10]`，唯一 expected deparse逐字为 `"FOR VALUES FROM ('"+F+" 00:00:00+00') TO ('"+T+" 00:00:00+00')"`，必须等于真实 `pg_get_expr` bytes。最后才由已验证F派生并核对relation suffix `yYYYYmMM`，禁止反过来由identity伪造bound。owner由`c.relowner -> pg_catalog.pg_roles.oid`逐字映射。column rows来自`pg_catalog.pg_attribute a`，过滤`a.attrelid=c.oid AND a.attnum>0 AND NOT a.attisdropped`，左连唯一`pg_catalog.pg_attrdef d ON d.adrelid=a.attrelid AND d.adnum=a.attnum`；`ordinal=a.attnum`，`name=a.attname`，`type_sql=pg_catalog.format_type(a.atttypid,a.atttypmod)`，`collation_sql`在`a.attcollation=0`时为null，否则由`pg_collation/pg_namespace`组成`quote_ident(nspname)||'.'||quote_ident(collname)`，`is_nullable=NOT a.attnotnull`，`default_sql`在无d row时为null、否则逐字取`pg_catalog.pg_get_expr(d.adbin,d.adrelid,false)`。`a.attidentity`只允许`''/'a'/'d'`并依次映射`none/generated_always/generated_by_default`，`a.attgenerated`必须为空字符串。按relation identity的Unicode code point、再按`a.attnum`数值升序，ordinal必须连续；`format_type/pg_get_expr`结果是manifest唯一type/default/bound字符串，文中展示型SQL别名不能覆盖它。
3. constraint query从controlled target relation及其`conparentid` descendants读取完整closure，不把该查询描述为全数据库universe。manifest仍且仅含两个parent table上`conparentid=0 AND contype IN ('p','u','f','c')`的二十一项root；`p/u/f/c`依次映射`primary_key/unique/foreign_key/check`，semantic identity=`relation_identity||'.'||conname`，definition逐字取`pg_catalog.pg_get_constraintdef(oid,false)`。在任何DDL前，两个FK的referenced precondition必须逐字证明：`public.organizations`与`public.users`各自唯一存在、`relkind='r'/relispartition=false/relpersistence='p'`且没有`pg_inherits`parent；`id`都是唯一non-dropped、`format_type='uuid'`、NOT NULL列；`public.organizations.pk_organizations`与`public.users.pk_users`各是`contype='p'/conparentid=0/convalidated=true/condeferrable=false/condeferred=false`、`conkey`只含相应`id`attnum，且各自`conindid`指向`indisvalid/indisready/indislive/indisunique=true`、`indpred/indexprs=null`的唯一backing index。两个manifest FK `fk_operation_logs_organization_v1/fk_operation_logs_actor_v1`必须分别以`organization_id/actor_id`引用上述exact relation/key/index，`confupdtype='r'/confdeltype='r'/confmatchtype='s'`。

   以二十一项root OID为depth 0递归遍历`child.conparentid=parent.oid`直到不动点。每个derived constraint必须恰有一个immediate parent、一个root和唯一正depth；cycle、orphan、多个root、重复semantic identity或额外local constraint均失败。对于PostgreSQL 16 parent-managed clone，`pg_depend`只在constraint lineage中验证：primary partition edge`P`指向immediate parent constraint，secondary edge`S`指向该child relation；不把P/S错误要求到trigger。derived row按kind继承root的`contype/definition/convalidated/condeferrable/condeferred/connoinherit`，固定`conislocal=false/coninhcount>=1`，relation必须是root relation的真实partition descendant；p/u/f的backing index、referenced relation/key/operator arrays逐项闭合。在已冻结的两侧拓扑下，每个FK root在四个初始child各有唯一derived FK，故FK derived子集固定为`2×4=8`；其他root的derived数量仍由同一递归closure派生，不恢复旧的总数硬编码。

   `derived_constraint_facts`为运行时派生数组，每项精确九键`semantic_identity/root_identity/parent_identity/depth/relation_identity/constraint_kind/definition_sql/backing_index_identity/dependency_edges`；depth为正integer，backing index仅按kind允许null，dependency edges使用第1步exact shape。parent-managed clone的dependency set恰为上述P/S pair；其他derived kind若PostgreSQL 16没有该pair必须为空，禁止自由edge。全数组按`(root_identity,depth,relation_identity,semantic_identity)`排序且唯一；FK-root条目恰为8。controlled post新增constraint恰为二十一root与该数组全集；derived不进入manifest `objects`，不改变`constraint_count=21/object_entry_count=435`。
4. index rows 从 `pg_catalog.pg_index i` 联接 index/table 的 `pg_class`、`pg_namespace` 与 `pg_am`，读取 `i.indrelid` 属于全部六个 relation 的所有 rows，不按名称、valid flag 或期望计数预过滤；index class 必须由 DDL owner持有且 `relpersistence='p'/reltablespace=0`，每行必须 `indisvalid/indisready/indislive=true`、`indpred/indexprs=null`、access method=`btree`。`key_signature` 逐字取 `pg_catalog.pg_get_indexdef(i.indexrelid,0,false)`。kind 按互斥优先级映射：index OID 在 `pg_inherits.inhrelid` 恰有一条 parent index edge时为 `attached_child`，并由 `inhparent` 解析唯一 `attached_parent_identity`；否则 index relation `relkind='I'` 且 `pg_constraint.conindid=i.indexrelid` 恰一行时为 `constraint_backed_partitioned`，`relkind='I'` 且无该 constraint时为 `partitioned`，`relkind='i'` 且恰一条 constraint时为 `constraint_backed`；其他组合拒绝。前三类 attached parent 必须 null，child 必须 non-null。按 relation identity、再按 index identity 的 Unicode code point 升序，结果必须恰为八个 parent/state index加二十四个 child index；重复/额外 index 不得被 allowlist filter 隐藏。
5. non-internal trigger query 读取六个 revision relation 上全部 `pg_trigger t` 且 `tgisinternal=false` 的 rows并联接 `pg_class/pg_proc`，结果必须恰为 manifest 十项；本查询只封闭 target relation，不冒充范围外 trigger审计。十项固定 `tgconstraint=0/tgdeferrable=false/tginitdeferred=false/tgenabled='O'/tgattr::smallint[]='{}'/tgqual IS NULL/tgnargs=0/octet_length(tgargs)=0`，`tgfoid` 全部解析为唯一 `public.reject_operation_log_mutation_v1()`。`tgtype` 按 PostgreSQL 16 bitmask 解码且只能是 row-before-update-delete 的 `1+2+8+16=27` 或 statement-before-truncate 的 `2+32=34`；parent 两项 `tgparentid=0`，四个 child row clone 的 `tgparentid` 必须分别指向 parent row trigger并映射 `parent_managed=true/parent_trigger_identity`，四个显式 child truncate 的 `tgparentid=0`并映射 false/null。`tgattr` 必须逐字映射 manifest `update_column_attnums=[]`，`tgname/relation` 生成稳定 manifest identity。任何禁用、`UPDATE OF`、condition、argument、错 function、错 bit、重复或 target relation 上额外 non-internal trigger都拒绝。

   internal RI query 从两个 root FK `fk_operation_logs_organization_v1/fk_operation_logs_actor_v1` 及第 3 步恰好八个 child FK constraint 出发，枚举其 referencing relation、referenced `public.organizations/public.users` 与 referenced PK index；再读取 `tgconstraint` 指向该十项 FK constraint 的全部 `tgisinternal=true` trigger，并要求 target closure 没有其他新增 RI internal trigger。PostgreSQL 16 冻结拓扑对每个 root 恰为十二项：referenced relation 上 root constraint 的 `restrict_delete/restrict_update` action 各一项，`operation_logs` parent 上 root constraint 的 `check_insert/check_update` 各一项，四个 child relation 上各自 derived constraint 的 `check_insert/check_update` 各两项；child constraint 不得拥有 action role。因此两个 root 总数精确为 `2×(2+2+4×2)=24`。四个 role 的 function identity分别固定为 `pg_catalog."RI_FKey_restrict_del"()`、`pg_catalog."RI_FKey_restrict_upd"()`、`pg_catalog."RI_FKey_check_ins"()`、`pg_catalog."RI_FKey_check_upd"()`，`tgtype` 分别为 row-after-delete `9`、row-after-update `17`、row-after-insert `5`、row-after-update `17`。任一 root/action、parent/check或child/check少一项、重复一项、child增加action、closure外新增RI trigger或closure内遗漏都失败。

ACL 的 grantee enum 顺序固定为 `PUBLIC` 后接上述十三角色顺序；privilege enum 顺序固定为 `ALL/SELECT/INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER/EXECUTE/USAGE/CREATE`；effect enum 顺序固定为 `revoke/grant`；ownership scope enum 顺序固定为 `external_precondition/revision_owned`。`ALL` 只允许与 `effect='revoke'`、`ownership_scope='revision_owned'` 组合；`EXECUTE` 只允许 function，表 privilege 只允许 relation，`USAGE/CREATE` 只允许 Schema `public`。每条 identity 逐字为 `object_identity|grantee|privilege|effect`；组件均禁止 `|`。唯一键是 `(object_identity,grantee,privilege,effect,ownership_scope)`，因此同一 object/grantee 的 `ALL/revoke` 与后续具体 privilege/grant 是两个不同合法行，不会被误判重复。

334 条 ACL row 只能由以下公式生成，先形成数学集合，再按全局 `(kind,identity)` 规则排序；不得依赖生成循环顺序：

1. `revision_owned` 先行撤销恰为 `O_owned × G_revoke` 的 300 行：`O_owned` 是本 manifest 六个 relation 与十九个 function 的全部 25 个 `identity`；`G_revoke` 按固定顺序恰为 `[PUBLIC,finaudit_migrator,finaudit_app_rw,finaudit_worker_rw,finaudit_bootstrap,finaudit_backend_boot,finaudit_worker_boot,finaudit_oplog_partition_scheduler,finaudit_oplog_chain_sealer,finaudit_restore_controller,finaudit_backup_ro,finaudit_audit_ro]`，即 `PUBLIC` 加全部十一个 LOGIN role。每个笛卡尔积元素固定 `privilege='ALL'/effect='revoke'/ownership_scope='revision_owned'`，所以 `25×12=300`。
2. `revision_owned` 后续 grant 恰为 26 行：relation grant 十一行——`public.operation_logs` 对 `finaudit_app_rw/finaudit_audit_ro/finaudit_oplog_chain_sealer/finaudit_backup_ro/finaudit_oplog_runtime_owner` 各 `SELECT`，另对 runtime owner `INSERT`；`public.operation_log_chain_state` 对 chain sealer/backup ro/runtime owner 各 `SELECT`，另对 runtime owner 各 `INSERT/UPDATE`。function grant 十五行——七个 append wrapper 分别向第 4.4 节唯一直接调用者授予一条 `EXECUTE`；`ensure_operation_log_partitions_v1` 向 partition scheduler 一条；initialize 向 migrator 一条；activate 向 migrator、restore controller 各一条；bootstrap completion 向 bootstrap 一条；sealer 向 chain sealer 一条；transition 与 restore completion 各向 restore controller 一条。全部固定 `effect='grant'/ownership_scope='revision_owned'`。
3. `external_precondition` 恰为八行：`public|PUBLIC|CREATE|revoke`、`public|PUBLIC|USAGE|grant`；`public.outbox_events` 对 runtime owner 的 `INSERT/grant`；`public.organizations/public.users/public.roles/public.user_roles/public.break_glass_requests` 各对 runtime owner一条 `SELECT/grant`。前两条 object 是 Schema，其余六条是既有 relation，全部固定 `ownership_scope='external_precondition'`。`public` actual owner=`finaudit_oplog_ddl_owner`是namespace catalog等式而非第九条ACL row，所以334/435不变。

最终 `acl_rule_count=300+26+8=334`。effective ACL verifier 必须先按 effect enum 语义应用 300 条 `REVOKE ALL`，再核对 26 条 revision grant，并独立核对八条只读 external precondition。PostgreSQL 隐式 owner 权限不展开为 ACL row 的例外只适用于 `ownership_scope='revision_owned'`，且 relation 的 `pg_class.relowner` 或 function 的 `pg_proc.proowner` 必须逐字等于同一 manifest object 的 `owner`；owner 缺失、错误或把非 owner 的权限当隐式权限都拒绝。

external scope没有runtime-owner例外：`public`Schema actual owner必须逐字为`finaudit_oplog_ddl_owner`；六个external relation分别解析唯一实际owner，该owner可为既有部署角色但必须不是`finaudit_oplog_runtime_owner`。验证器按上段唯一AclAtom算法展开全部ACL。对每个对象先在snapshot中保留全部atoms，再单独取`grantee=actual_owner`的rows，要求其privilege集合逐项等于PostgreSQL 16该object class的完整固有owner集合且没有伪造第三方grantee；只有owner等式与完整集合通过后，才在external effective ACL比较阶段排除这些actual-owner rows。实际owner不是manifest ACL grantee，不能把其合法固有owner rows误报为额外；该排除绝不适用于runtime owner，也不允许排除owner向任何非owner的grant。

排除经验证的 actual-owner rows后，剩余 direct ACL 必须严格等于八条 external manifest事实所表达的有效集合：PUBLIC 对 Schema 仅 `USAGE`且无 grant option，runtime owner 对 outbox 仅 `INSERT`、对其余五表各仅 `SELECT`且全部无 grant option，Schema `CREATE` 为 false，其他非 owner grantee在 Schema/六表均无权限。effective verifier 必须先通过上段 R13 双向 boundary，随后只为计算 runtime owner的角色可达性读取完整 `pg_auth_members` 图并递归 closure；因为任何连接 R13与external的第一条边已被 boundary拒绝，external→external子图不会产生 runtime路径也不应被全局“两边”假设误拒。再以 PostgreSQL privilege checks穷尽 Schema 的 `USAGE/CREATE` 和 relation 的 `SELECT/INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER`，证明 runtime owner最终 effective privilege仍恰为上述 `USAGE/INSERT/五项SELECT`，不存在经 PUBLIC、direct membership、indirect membership、owner冒充或 grant option得到的额外权限。`CREATE/revoke` 由 effective false证明；role membership 不编码为 ACL row，只能由十三个 role_requirement 表达。任一未知非 owner grantee、显式 grant、grant option、缺失 revoke前置或缺失/额外 row 都拒绝。

kind 的固定顺序为 `relation/constraint/index/trigger/function/role_requirement/acl_rule`，`objects[]` 按 `(kind enum ordinal, identity 的 Unicode code point)` 升序且全局 identity 不重复。`columns` 按 ordinal；`event_set` 按 `UPDATE/DELETE/TRUNCATE`；`direct_caller_roles/member_roles` 按十三角色 enum；`required_attributes/forbidden_attributes` 按 attribute enum；任一数组都无重复。`identity` 必须是本文 allowlist 中 schema-qualified relation、完整函数签名、`relation.constraint`、`relation.index`、`relation.trigger`、role 名或 ACL 四组件之一；不得用自由文本 kind、null 或额外 object variant 承载未知对象。

批准inventory只描述未来migration的封闭语句合同，不表示审批时文件已存在。实施验证器必须对无BOM UTF-8/LF的migration raw bytes先计算`migration_file_raw_sha256`，再以CPython 3.10 `ast.parse(...,feature_version=(3,10))`、manifest绑定的exact analyzer source和逐项source-hash已验证的compiler binding执行静态分析与offline compilation。module AST只允许可选首行literal docstring、精确imports `from alembic import op`、`import sqlalchemy as sa`、`from sqlalchemy.dialects import postgresql`、四个literal metadata assignment `revision/down_revision/branch_labels/depends_on`以及无参数`upgrade()/downgrade()`；两个函数body只允许上述六种`op.*`调用。参数子树只允许string/integer/boolean/null/tuple/list/dict literal以及封闭constructor enum `sa.Column/sa.PrimaryKeyConstraint/sa.UniqueConstraint/sa.ForeignKeyConstraint/sa.CheckConstraint/sa.Index/sa.text/sa.BigInteger/sa.Boolean/sa.DateTime/sa.Integer/sa.String/sa.Text/postgresql.UUID/postgresql.JSONB/postgresql.INET`；除这些constructor及`op.execute(<single literal string>)`外不得出现任意call。禁止name-derived SQL、f-string、concatenation、变量引用、loop、branch、comprehension、lambda、decorator、async、exception/with、dynamic import、file/environment/network/process访问、`eval/exec/getattr`或运行时反射。analyzer必须从每个DSL call的最终compiled SQL和每个literal SQL重建整个七键`ddl_statement_inventory`并与manifest JCS逐字相等；任一额外AST node、无法分类node、compiler source/version不等、bind parameter或inventory漂移都在连接数据库前失败。

每份DSL compiled SQL和literal SQL都必须由analyzer绑定的PostgreSQL 16 server-parser build完整切分并套用同一tag allowlist、identity allowlist与DML denylist；拒绝parse warning、空base command或trailing未消费bytes。显式DDL command-tag exact allowlist按此顺序为`CREATE TABLE/ALTER TABLE/CREATE INDEX/ALTER INDEX/CREATE FUNCTION/ALTER FUNCTION/CREATE TRIGGER/GRANT/REVOKE/DROP TRIGGER/DROP FUNCTION/DROP INDEX/DROP TABLE`；session-control只允许单一base command/tag=`SET`且raw语法逐字为`SET LOCAL ROLE finaudit_oplog_ddl_owner`或`SET LOCAL ROLE finaudit_oplog_runtime_owner`。所有identity必须属于manifest/registry binding且schema为`public`；upgrade不得含任何DROP，downgrade不得含任何CREATE/GRANT。`INSERT/UPDATE/DELETE/MERGE/TRUNCATE/COPY/SELECT/SELECT INTO/CALL/DO`、任意data-changing CTE、`CREATE/ALTER/DROP ROLE|DATABASE|TABLESPACE|EVENT TRIGGER`、`ALTER SYSTEM`、`CREATE EXTENSION/TYPE/POLICY/COMMENT/SEQUENCE/VIEW/MATERIALIZED VIEW/SCHEMA`、transaction/prepared-statement命令及任何不在上述exact allowlist的statement一律静态拒绝；因此DSL raw fragment、unsupported shared-object或event-trigger DDL都不能借compiler/event-trigger盲区通过。downgrade topology/nonempty preflight仍由受保护validator/deployer在同一数据库事务先执行并持续持有migration/advisory/table locks，再在该事务调用`downgrade()`；这些trusted preflight queries不属于migration Python raw bytes，不得被搬入DSL、literal SQL或另开事务来绕过`BLOCK_BEFORE_DDL`语义。

disposable database在载入migration前由不属于R13的validator superuser预装受保护validator schema、四个event trigger function、四个event trigger与单一append-only ledger relation。`validator_binding`精确七键`validator_role/validator_schema/event_triggers/event_functions/ledger_relation/migration_role/source_bundle_sha256`：role/schema固定`cr006_validator/cr006_validator`，migration role固定`finaudit_migrator`，source hash为Sha256。`event_triggers`恰四项、按event enum `ddl_command_start/ddl_command_end/sql_drop/table_rewrite`排序，每项精确六键`identity/event/owner/enabled_mode/function_identity/tag_allowlist`；owner固定validator role，enabled mode固定`always`并逐字验证`evtenabled='A'`，start的tag allowlist恰为上述DDL tag enum，其他三项为`[]`。`event_functions`恰四项并按identity排序，每项精确七键`identity/owner/language/security/search_path/body_source_sha256/execute_acl_atoms`，固定owner、`plpgsql/definer/[pg_catalog,cr006_validator]`且EXECUTE只给validator、无grant option。`ledger_relation`精确五键`identity/owner/relkind/persistence/acl_atoms`，固定`cr006_validator.cr006_ddl_event_ledger`、validator owner、`r/permanent`且迁移角色/PUBLIC无任何ACL。pre/post必须分别从`pg_event_trigger/pg_proc/pg_class/ACL`重构该七键对象；owner、ENABLE ALWAYS、function source/search_path/ACL、trigger tags或ledger ACL任一变化即失败。

`migration_principal_binding`精确十二键`session_user/is_superuser/inherits_roles/bypassrls/can_createdb/can_createrole/can_replication/allowed_set_roles/can_alter_system/can_create_extension/can_manage_event_triggers/can_modify_validator_objects`；session user固定`finaudit_migrator`，十个`is/can` capability boolean全部false，allowed set roles按role enum恰为`[finaudit_oplog_ddl_owner,finaudit_oplog_runtime_owner]`。验证器以该session user运行migration，只接受inventory中的exact `SET LOCAL ROLE`；R13 boundary与三option仍必须通过，任何其他SET ROLE、session authorization、validator schema写入或shared/event-trigger管理能力都拒绝。

受保护`ddl_command_start`在每个base DDL执行前按inventory的全局base顺序fail-closed核对command tag与current/session role；`ddl_command_end`记录该base的`pg_event_trigger_ddl_commands()`全部rows并按inventory五键event multiset合并比较，一个SQL fragment可有多个base command且一个base command可有零到多条catalog row，禁止假设1:1。`table_rewrite`在执行前记录relation与reason并一律抛错；成功run的rewrite集合必须为空。event trigger不为PostgreSQL自动派生的constraint clone、attached index或internal RI trigger虚构显式create command；这些对象仍且只由controlled catalog constraint/index/RI closure证明。closed AST/compiled-SQL inventory、受保护event ledger与controlled catalog projection三证必须同时为真。

downgrade drop proof使用独立`PG16 dependency drop closure`，不得复用、裁剪或声称等同controlled catalog closure。empty与nonempty downgrade run都必须在任何DROP前、同一锁定post-upgrade catalog snapshot中按downgrade inventory全局base顺序解析每个显式DROP target为唯一`(classid,objid,objsubid)`root；upgrade closure固定`[]`。验证器模拟RESTRICT drop顺序：对当前仍存在的root先加入depth=0/`dependency_type='root'`，再按PostgreSQL 16 whole-object语义反向读取`pg_depend`：current `objsubid=0`时predicate必须为`refclassid=current.classid AND refobjid=current.objid`且不限制`refobjsubid`，current `objsubid<>0`时才精确比较`refclassid/refobjid/refobjsubid`三元组，遍历`deptype IN ('a','i','P','S')`到不动点；`n/e/x`或未知edge绝不遍历，出现会要求CASCADE、extension ownership或范围外对象时直接失败。whole-object匹配到的column-level `refobjsubid>0`edge必须先验证该`pg_attribute`存在且未删除，再把`parent_semantic_identity`折叠为该column所属enclosing relation的semantic identity，不生成column semantic item。每个root closure从模拟catalog移除后才处理下一root；已被较早root自动移除的后续显式target、cycle、orphan、同一address多个stable identity或未消费explicit root均失败。同一depender physical address可由多条合法`pg_depend`row到达，不得因row不唯一而失败；先把每条边投影为候选item，再对同address依次选择最早inventory root、最小depth、dependency type enum`a/i/P/S`最小值、以及折叠后`parent_semantic_identity` Unicode code point最小值进行deterministic coalesce。root的parent固定null，非root保存coalesce选中且与真实edge一致的直接semantic parent。最终数组按`(root inventory ordinal,depth,dependency_type enum root/a/i/P/S,semantic_identity Unicode code point)`排序，coalesce后physical address与semantic identity都唯一。

drop semantic kind封闭为`class/type/constraint/trigger/attribute_default/procedure`。显式relation/index/function/constraint/trigger使用manifest或controlled semantic identity；relation生成的composite row type、array type、TOAST table与TOAST index分别映射`relation_identity|row_type`、`relation_identity|array_type`、`relation_identity|toast_table`、`relation_identity|toast_index`；column default映射`relation_identity|column_name|default`；derived constraint与RI trigger使用第3/5步semantic identity。TOAST不使用实例OID派生名作semantic identity：在DROP前的同一snapshot中，base relation必须以`pg_class.reltoastrelid`唯一指向该TOAST table physical address并用其internal/auto dependency验证table映射。TOAST index不要求唯一dependency edge；必须以`pg_index.indrelid=toast_table_oid`查得恰一个`indexrelid`并验证该唯一index object，再以`pg_attribute`解析TOAST table未删除的`chunk_id/chunk_seq`两列attnum，要求该index physical address指向这两列的`pg_depend` AUTO edge set恰为两条、无缺失、额外或重复。这两条column edge均按上段折叠为`parent_semantic_identity=relation_identity|toast_table`并deterministic coalesce，closure只生成一个`relation_identity|toast_index`semantic item。base relation、TOAST table、TOAST index三者physical address、`pg_index`对应或完整两边set任一不等即失败。其他pg_catalog class、shared object、external relation/key、validator object或无法唯一映射的address一律拒绝。该closure必须包含真实依赖可达的row/array type、TOAST relation/index、constraint/index/trigger/default及其他上述allowed kind，不能靠命名allowlist漏掉内部对象。

expected semantic drop item精确九键`semantic_identity/root_semantic_identity/parent_semantic_identity/depth/dependency_type/object_type/original/normal/is_temporary`，不得包含OID、physical address、`schema_name/object_name/object_identity/address_names/address_args`或其他实例派生值。`semantic_identity/root_semantic_identity`的类型为non-null string，`parent_semantic_identity`的类型为`string|null`；depth为非负integer。root item固定`root_semantic_identity=semantic_identity/parent_semantic_identity=null/depth=0/dependency_type='root'/original=true/normal=false`；a/i/P/S dependent固定parent为non-null且存在于同root的更小depth、`depth=parent.depth+1/dependency_type∈a/i/P/S/original=false/normal=false`。`original=false/normal=true`只代表CASCADE沿normal dependency删除，因所有DROP固定RESTRICT而禁止；`original=true/normal=true`为不可能组合并拒绝。`is_temporary=false`。PostgreSQL 16 `object_type`enum按此顺序固定为`table/toast table/index/type/table constraint/trigger/default value/function`；TOAST table必须使用`toast table`，TOAST index使用`index`。expected closure是九键item数组，按上段唯一顺序排序并以`SHA256(JCS(expected_drop_closure))`生成stable semantic closure hash；两个同构downgrade run只要求该semantic array/hash逐字相等。

`sql_drop`必须读取`pg_event_trigger_dropped_objects()`每一raw row且不得先按type/schema/name过滤；在该database instance的DROP前snapshot中raw`classid/objid/objsubid`必须唯一解析semantic identity。observed raw item精确十键`semantic_identity/original/normal/is_temporary/object_type/schema_name/object_name/object_identity/address_names/address_args`；前四项为`string/boolean/boolean/boolean`，`object_type/object_identity`为non-null string，`schema_name/object_name`为`string|null`，两个address字段均为不含null的`array<string>`且本closure中non-null。raw object type使用上段含`toast table`的exact enum；schema在本closure全部non-null，object name仅`table/toast table/index/type`为non-null，`function/table constraint/trigger/default value`固定null。table/toast table/index/type的names非空、args=`[]`；function的names非空、args为真实identity argument type string数组且可空；constraint/trigger/default的names非空、args=`[]`；两个array逐项保留PG返回顺序。

非TOAST item必须以raw`object_type/address_names/address_args`调用`pg_get_object_address`并round-trip回同一pre-drop physical address；TOAST table及其index禁止将实例名交给generic `pg_get_object_address`，只能用上段`reltoastrelid`、TOAST index relation edge与raw physical address三方等式验证后映射stable identity。所有raw`object_identity/object_name/address_names/address_args`保留在observed ledger JCS中，允许在两个disposable database间不同，不参与跨run等式。对每个observed item，验证器以已验证的physical edge查回expected item的root/parent/depth/dependency type，再投影为九键semantic item；每个base的observed semantic projection必须逐项等于expected closure对应slice，全run flatten后再等于完整semantic closure。缺失、额外、重复、flag/null/physical mapping不等、CASCADE normal row、external/validator object或upgrade drop均抛错回滚；绝不要求两个database的observed raw rows/JCS相等。

`ddl_event_ledger`根精确九键`ledger_version='cr006-ddl-event-ledger-v1'/validator_binding/migration_principal_binding/pre_validator_state_sha256/post_validator_state_sha256/inventory_sha256/migration_raw_sha256/runs/row_counts`。两个state hash都必须等于实际pre/post七键validator binding的JCS hash且彼此相等；inventory hash=`SHA256(JCS(manifest.ddl_statement_inventory))`，raw hash等于attestation同名字段。`runs`恰三项并按`upgrade/empty_downgrade/nonempty_downgrade`排序，每项精确十四键`run_kind/phase/database_instance_id/session_user/inventory_sha256/migration_raw_sha256/expected_drop_closure/expected_drop_closure_sha256/expected_outcome/observed_outcome/start_events/end_events/drop_events/rewrite_events`；phase依次为`upgrade/downgrade/downgrade`，outcome enum为`COMMIT/BLOCK_BEFORE_DDL`且expected必须等于observed，三个binding字段逐项等于root。closure使用上述九键stable semantic item，hash=`SHA256(JCS(expected_drop_closure))`；upgrade固定`[]`及其JCS hash，两个downgrade run在同构post-upgrade catalog上必须得到逐字相等的non-empty semantic closure/hash，不比较其instance-specific observed raw rows。nonempty downgrade必须`BLOCK_BEFORE_DDL`且四个event数组全为`[]`，但仍保存DDL前已计算的expected closure；另两项必须COMMIT，start/end覆盖inventory相应phase全部DDL base，upgrade drop为空，empty downgrade的drop event semantic projection flatten恰等于closure，rewrite均为空。

start item精确六键`sequence/statement_id/base_ordinal/command_tag/session_user/current_user`；end item精确五键`sequence/statement_id/base_ordinal/command_tag/event_set`且event set使用inventory五键shape；drop item精确五键`sequence/statement_id/base_ordinal/command_tag/dropped_objects`，dropped objects使用上述十键observed raw item shape；rewrite item精确六键`sequence/statement_id/base_ordinal/relation_identity/reason_mask/reason_codes`，reason enum顺序为`persistence/default_expression/column_type/access_method`且mask与数组双向等价。sequence为每run从1连续正integer；reason codes排序唯一，drop address arrays保持PG返回顺序；所有event数组均non-null且无null item。除observed raw item明示的`schema_name/object_name`null matrix外，ledger字段不得null。`row_counts`精确四键`ddl_command_start/ddl_command_end/sql_drop/table_rewrite`，均为非负integer并分别等于三个run对应数组length之和，table rewrite固定0。

manifest 的 path/revision 生命周期矩阵固定为：联合审批时目标 migration file 必须不存在，manifest 只保留经唯一-head preflight 预留的 path/revision/down_revision与planned inventory；获另行实施授权后只能在该预留路径创建恰好一个 owned revision，文件内部 revision/down_revision 必须逐字匹配 manifest，registry SQL 必须匹配`registry_binding`，静态analyzer重构的inventory也必须逐字匹配`ddl_statement_inventory`；任一 file 已存在、head 漂移、额外 owned revision、raw AST/SQL、对象集合或计数漂移都在执行 DDL 前失败并要求提升 CR revision，禁止自动换号、改 path、放宽analyzer或接管对象。

MIGRATION规则固定为：`MANIFEST_435_VALID`要求十三键manifest、含exact compiler binding/non-null SQL hash的七键planned inventory、十二键counts、101个非ACL对象、334个ACL rows、435个sorted unique objects全部通过；三个FAIL分别只改一个count而不改objects、只交换相邻objects、只添加一个well-typed额外object，并产生表列error。CATALOG规则固定为：`CATALOG_FULL_DELTA_VALID`要求compiled-SQL inventory、protected ledger、independent downgrade drop closure（含whole-object subid fan-in、column-parent fold与TOAST two-AUTO-edge coalesce）、controlled target projection三证及十二键projection全部通过；`CATALOG_ATTESTATION_UPGRADE_FAILED_NULL`要求upgrade=false、projection hash=null、match=false与双failure code矩阵；`CATALOG_ATTESTATION_MISMATCH_HASH_PRESENT`要求upgrade=true、真实projection hash non-null、match=false且只有对应catalog code。六个FAIL依次要求：一个preexisting controlled identity的post item bytes改变；migration创建再删除恰一个inventory外对象，使ddl end event多一个tuple且sql_drop多一个observed raw item，其semantic projection含一个不在expected stable closure的semantic identity，而controlled pre/post target可保持不变；一个derived constraint fact改变；24项RI semantic fact缺失一项或把8×2/16×4 dependency matrix任一edge改变；一个non-internal trigger的`update_column_attnums`变为单attnum；一个`character`argument identity伪写为`character(64)`；各自其余更高优先级条件通过并产生表列error。

ACL规则固定为：`ACL_334_VALID`要求public Schema owner=`finaudit_oplog_ddl_owner`、n/r/f acldefault唯一AclAtom映射、index空ACL、exact334 manifest rows、snapshot owner atoms保留、后续actual-owner排除与effective closure全部相等；三个FAIL分别令一个external relation actual owner等于runtime owner、给PUBLIC增加一个有效privilege、把一条允许grant改为grant option=true。MEMBERSHIP规则固定为：`MEMBERSHIP_R13_VALID`要求R13 induced boundary恰为migrator→两个owner且option为false/false/true；`MEMBERSHIP_EXTERNAL_EXTERNAL_IGNORED`只增加一条两端均不在R13的edge且boundary不变；三个FAIL分别增加`member∈R13/roleid∉R13`、`roleid∈R13/member∉R13`的一条edge，或只翻转一项approved edge option。RESTORE规则固定为：两个PASS分别验证fresh非零历史epoch等于C first-log UTC date、day-anchor epoch恰为parent-plus-one；三个FAIL分别令fresh零行或snapshot-tail的G跨锁定state UTC date stale，或只使H/evidence/plan三键transition之一不等。SNAPSHOT规则固定为：两个PASS分别要求LF raw中exact marker一行一次、CRLF raw经唯一CRLF→LF normalization后得到同一normalized bytes；三个FAIL分别令exact marker出现两次、零次、或只出现带前后whitespace的近似行。

同category的FAIL error优先级固定为上表从左到右；recipe必须使目标error成立且所有更高优先级error predicate通过，若多个失败则只返回首项。PASS必须通过完整category validator和其同名positive rule。`expected_outcome`只允许`PASS/FAIL`；recipe与case的outcome/error/transform逐项相等。PASS固定`expected_error_code=null/pass_output_transform=<category transform>/expected_receipt=ExactCaseReceipt`；FAIL固定error为表列non-null enum、transform=null、receipt=null。

category transform enum一一映射为`ROW_HASH_EXACT/CHAIN_HASH_EXACT/MIGRATION_MANIFEST_EXACT/CATALOG_PROJECTION_EXACT/ACL_EFFECTIVE_EXACT/MEMBERSHIP_BOUNDARY_EXACT/RESTORE_C_G_H_EXACT/SNAPSHOT_BOUNDARY_EXACT`。`ExactCaseProjection`按transform为封闭oneOf：ROW精确三键`row_sha256/paired_row_sha256/equivalence_proven`，paired仅negative-zero case为Sha256且equivalence=true、其他PASS为null/false；CHAIN精确三键`artifact_set_sha256/final_chain_sha256/no_replace_result`，result enum为`not_applicable/created/reused`；MANIFEST精确二键`object_counts_sha256/objects_sha256`；CATALOG精确三键`projection_sha256/catalog_matches_manifest/projection_hash_present`，projection仅upgrade-failed-null case为null且present=false、其他PASS为Sha256/true，match仅full-delta case为true；ACL精确二键`direct_acl_sha256/effective_privilege_sha256`；MEMBERSHIP精确一键`r13_boundary_sha256`；RESTORE精确二键`binding_projection_sha256/transition_sha256`；SNAPSHOT精确二键`normalized_bytes_sha256/marker_count`且marker count=1。除上述两个显式nullable hash外所有projection字段non-null；每个Sha256都只由本文对应exact algorithm的真实output计算。

`ExactCaseReceipt`精确八键`receipt_schema_version='cr006-fixed-vector-receipt-v1'/case_id/category/semantic_predicate_id/input_sha256/output_transform/derived_value_sha256/predicate_result='PASS'`，其中`derived_value_sha256=SHA256(JCS(ExactCaseProjection))`。每项`implementation_results`恰两项并按root implementation顺序，每项精确四键`implementation_id/outcome/receipt/error_code`：PASS receipt逐字等于expected且error=null；FAIL receipt=null、error逐字等于expected。两实现的outcome/receipt/error必须逐项相等；缺失、skip、共享实现或仅比较digest而不重构projection均拒绝bundle。

唯一生成DAG固定为`generator source ref/hash + base fixture raw ref/hash + recipe_set_sha256 → generated case input bytes → two implementation results/receipts → vector root raw JCS bytes → joint artifact raw hash`，根中不保存自身hash且无反向引用。review snapshot时generator/base/recipe/input/receipt bytes仍未共同绑定，可能存在多个candidate，任何candidate都不算approved artifact；后续必须由共同approvers一次性复核并在`cr006_fixed_vectors`artifact role绑定exact generator source ref/hash、base fixture ref/hash、57项recipe paths/values、57项generated input bytes、两实现结果及最终raw hash。绑定后同role/hash no-replace，任何generator、fixture、recipe、case bytes或result改变都必须提升CR revision并重新联合审批，不能原地替换。

共同类型固定为：UUID 使用小写连字符；UUIDv4 校验 version/variant；UTC timestamp 恰好六位小数和 `Z`；UTC date 为真实公历 `YYYY-MM-DD`；SHA-256 为小写 64 hex；SafeInteger 为 `0..9007199254740991`。`partition_kind` 仅 `range/default`；range bound 使用 UTC 六位微秒，default 两端均 null。object 数组按本文主身份 Unicode code point 升序并拒绝重复。第 3.4/3.5 节列出的 genesis、daily manifest、verification 和 difference 精确键/null matrix 必须直接编码；跨字段相等、日期顺序、JCS/hash、partition catalog、migration counts/registry binding、C/G/H 相等和 no-replace 由 `cr006-companion-validator-v1` 与测试向量验证。bundle 内每个文件的相对路径、byte length 和 SHA-256 由外部审批清单绑定，本文不预填 hash。

### 4.6 Upgrade、activation 与 downgrade 顺序

upgrade 固定顺序：对raw migration执行CPython 3.10封闭AST、验证三套compiler version/source并hash每项最终compiled/literal SQL，逐字匹配七键approved inventory → disposable验证库由validator superuser预装且复核ENABLE ALWAYS event guards/ledger，migration principal权限收敛 → 外部停服务/调度并验证角色、R13 boundary、`public`owner=`finaudit_oplog_ddl_owner`及八条external ACL precondition → 核对唯一head/object、取得migration lock并生成pre controlled target snapshot/hash，同时证明两个专用owner的public class/proc subset为空 → 以`finaudit_migrator`且只SET ROLE两个owner执行inventory：创建两父表但不建state row → 创建current+2/default → 创建/attach全部index → 创建函数和triggers → 安装经hash验证的registry SQL → 只执行300条`revision_owned REVOKE ALL`后再执行26条精确`revision_owned grant` → 生成post controlled target snapshot/hash/delta，校验owner subset、recursive constraint、24项RI trigger及8×2/16×4 dependency facts、catalog/object manifest、AclAtom和八条只读external ACL → 比较完整event ledger与validator post-state → 提交。Alembic绝不修改external ACL、不执行DML、不访问MinIO、不创建state、不运行bootstrap、不启动服务；closed inventory、ledger或controlled projection任一失败即回滚。提交后由受控部署按第3.4节执行state→genesis→initial bootstrap→enablement saga；任何失败保持append disabled和ingress closed。

downgrade 前外部流程必须停服务/调度、只读验证 MinIO 制品仍存在且 no-replace、撤销 producer EXECUTE。受保护数据库事务依次取得migration lock、锁两父表及后代、验证精确topology，并在任何DROP前由downgrade inventory explicit roots独立计算PG16 dependency drop closure/hash；随后要求全部分区零行且state表零行，任一不满足在DDL前失败但attestation仍保存expected closure。通过后按依赖逆序执行：删除每个 child/default 的显式 TRUNCATE trigger → 删除父表两项 trigger，其中父级 row trigger 只通过其 parent DROP 清除 PostgreSQL 管理的 partition clones → 删除五个父级查询 partitioned index，由其依赖关系清除已 attach 的 child index → 删除 `operation_logs_pkey` 约束并由其依赖关系清除父/child 主键索引 → 删除 state unique/primary-key 约束及其索引 → 删除七个 wrappers，再删除 completion/transition/sealer/activation/initialization、append/registry/JSON validator、ensure/lock/helper/trigger functions → 删除 current+2/default 四个 partition relation → 删除 `operation_logs` 与 `operation_log_chain_state`。每个显式DROP使用manifest精确签名/名称、固定RESTRICT且禁止CASCADE；每个sql_drop raw slice必须全量保留，单实例TOAST physical edge映射后，其semantic projection及全run projection flatten必须逐项等于independent stable semantic closure；不得比较两个database的raw实例名/address，也不得直接DROP或漏记PostgreSQL内部依赖的row/array type、TOAST、default、trigger clone、attached child index等对象。不得删除 external artifact、角色、先前 revision 对象，也不得恢复 `PUBLIC CREATE`或改变public owner。空库重新 upgrade 后必须生成新 chain ID。

## 5. 必须验收

- **列与归属**：NULL/未知 `result` 由 PostgreSQL 拒绝；合法三态通过。删除被引用组织失败；NULL 组织只允许批准的 system-global 动作，组织级事件和非空 actor 不能借 NULL 绕过。
- **PostgreSQL 16 Schema 与 object manifest**：真实数据库逐项对照`cr006-migration-object-manifest-v1`；封闭CPython/compiler/SQL inventory、validator-owned event ledger与五catalog controlled target projection三证合取，禁止由projection单独声称发现所有PostgreSQL对象。controlled pre/post/delta必须保持`public`namespace owner=`finaudit_oplog_ddl_owner`、无namespace新增、无target identity删除或修改，新增恰为38 class、19 proc、21 root constraint、recursive derived constraint closure、10 non-internal trigger和精确24项RI internal trigger；专用owner subset另须为空→38/19精确归属。两父表全部列、persistence/default tablespace、真实partition bound、八个parent/state index、二十四个child index、十个manifest trigger、十九个canonical函数、十三个ACL role及精确GRANT/REVOKE均无缺失或额外target对象。验证必须实际调用`format_type`、`pg_get_expr(...,false)`、`pg_get_constraintdef(...,false)`、`pg_get_indexdef(...,0,false)`、`pg_get_function_identity_arguments`和`pg_get_function_result`并逐UTF-8 bytes比较；`organizations/users` ordinary/nonpartitioned及PK precondition、constraint递归lineage、RI trigger跨referencing/referenced relations、semantic identity与8项n+i/16项n+i+P+S dependency matrix、non-internal`tgattr=[]`、target pg_trigger/pg_proc/proconfig/caller、body LF/TAB hash均必须通过。namespace/relation/function AclAtom必须分别使用n/r/f acldefault唯一投影，index固定空，owner atoms先保留后排除；R13双向membership boundary恰为两条三option edge，同时允许无关external→external edge。六个external relation actual owner不能是runtime owner，runtime effective privilege恰为USAGE、INSERT、五项SELECT且无grant option或额外PUBLIC/membership权限。future partition每个仍恰有六个child index和两个non-internal trigger，其constraint派生数由递归算法计算，RI拓扑按相同parent/child语义验证。companion必须拒绝path/revision/head、compiler/inventory/ledger/validator保护、controlled delta、public owner、AclAtom、owner subset、kind/identity/排序/计数、registry binding及任一target额外/缺失/修改对象；真实catalog重算counts与manifest逐项相等。相同`(created_at,id)`被拒绝，不同二元组通过；head/file/object preflight任一漂移都在DDL前失败。
- **Migration implementation attestation**：批准后只在disposable PostgreSQL 16创建预留migration，重算file raw hash；封闭analyzer验证三套compiler source并重构七键approved inventory，validator-owned ENABLE ALWAYS guards记录三项十四键run、两个downgrade九键stable semantic expected closure/hash、whole-object/subid遍历与multi-edge coalesce、TOAST `pg_index`两AUTO-edge等式，以及empty-run十键raw sql_drop及semantic projection等式，controlled target projection记录pre/post hash、delta、derived constraints、精确24项RI facts及owner subset，并逐列验证catalog bound、constraint、index、trigger、十九项pg_proc/prosrc、AclAtom/actual owner、R13 membership、effective privilege与registry SQL。三证、独立drop closure与validator保护状态必须合取；成功release实例的upgrade、catalog等式、空库downgrade和非空库DDL前阻断四项都必须为true。upgrade失败或projection未形成时catalog hash必须null且match=false；upgrade成功并形成projection时即使inventory/ledger/catalog任一mismatch也必须保存non-null真实hash。失败诊断实例、缺joint record/manifest ref、head漂移或未由另行release authorization绑定的成功attestation均不得用于目标migration。
- **OPS-004 Cursor**：覆盖首屏上界、并发追加、同微秒多个 UUID、`operation-log-filters-v1` 的 absent/null、大小写、空白、等价时区、半开区间、requester/过滤器/角色/数据范围变化、跨用户 cursor 重放、HMAC payload 任一字段篡改、未知/轮换 kid、过期、超长、错版、截断、最后一页和 `page` 混用；先验签再使用位置，复合 keyset 无重复、无漏项且每页重新鉴权，跨 requester 重放固定返回 `CURSOR_SCOPE_CHANGED`。

- **维护与默认分区**：重复运行部署调度不改变既有边界；并发维护由 advisory lock 串行；调度角色只能 EXECUTE 无参数 definer wrapper，临时同名对象、原始 SQL、任意日期和 owner/migrator 凭据均不可利用，不创建 system-global `async_jobs`。漏建月分区时函数返回 `landed_in_default`，同事务 Outbox 在业务回滚时消失、提交后可恢复投递，外部告警按日志二元身份去重且不递归 INSERT；查询、哈希和备份不漏行，默认分区非空时禁止破坏性搬移或重叠 ATTACH。

- **迟交事务与水位**：除覆盖 23:59:59 已取得共享锁后延迟提交外，必须精确暂停在“首次取候选时间后、取得共享锁前”，让封账先提交水位，再证明恢复调用会重新取锁后时间并归入新日；另覆盖封账等待、封账期间新写、三次时钟不稳定、墙钟稳定回拨到已封账日、状态行 CAS、MinIO 发布失败重试和 privileged restore。任何 `candidate_day <= sealed_through_utc_date` 的新行都由数据库拒绝，不能落在已发布或已提交待发布的锚点之外。
- **哈希固定向量**：精确执行上表ROW_HASH与CHAIN_HASH case，输入覆盖NULL、Unicode、IPv4/IPv6、角色数组、嵌套JSON、安全整数边界、越界整数、普通字符串`"001"`、合法/非法`$decimal`标签、小数和指数及期望行摘要/日锚点。negative-zero唯一使用`operation_log_row_lexeme_pair_fixture_v1`JCS envelope内两份完整raw JSON row bytes，严格证明仅numeric lexeme`-0/0`的单minus差异，经lexeme-aware parse、PostgreSQL JSONB、JCS、row preimage后值与hash一致；不得声称JCS自身保留`-0`。数据库导出端和独立校验端恰好两种实现必须得到逐字节相同结果。

## 8. Decision snapshot 算法与变更控制

CR-006 decision snapshot 覆盖本文件静态头和第 1—8 节，算法固定为：

1. 读取本文件原始 bytes；拒绝非法 UTF-8、UTF-8 BOM 或其他编码。
2. 将 `CRLF` 和孤立 `CR` 统一转换为 `LF`；不做 Unicode normalization。
3. 按 LF 分行；marker bytes 定义为 `UTF8("## 9." + U+0020 + "当前" + "状态")`，以 ordinal byte-equivalent 比较，行首/行尾不得有额外空格或其他字符；该完整行在全文件必须恰好出现一次，零次或多次均失败。
4. 取 marker 行之前全部内容，移除末尾已有的所有 LF，再追加且只追加一个 LF。
5. 以无 BOM UTF-8 编码；不裁剪行尾空格、不改写 Markdown、不替换全角/半角字符。
6. 对所得 bytes 计算 SHA-256，输出 64 位小写十六进制；生成前不得预填或猜测，生成后可写入第 9 节 `GENERATED_FOR_REVIEW / NOT APPROVED` 状态行，并由后续外部 no-replace review/审批记录逐字复用。
7. 生成前必须机械检查第 1—8 节无未解释占位值、SQL 对象全部进入封闭 allowlist、未硬编码最终核心表总数，且 object/function/role/artifact allowlist 自洽。静态前缀通过这些检查后即可生成首次 `snapshot_purpose=contract_review` 的 review snapshot；该 snapshot 必须明确 `approval_state=NOT_APPROVED`，不声称外部 artifact 已生成或已批准，也不授权 migration/runtime。
8. 若外部 Schema/instance/companion/vector/registry/Handler、DEP-005 approval record set 或 post-sync attestation 未绑定，则只阻断共同批准、migration 和 runtime，不阻断第 7 步静态 review snapshot。任何运行时状态值、占位符、全零或猜测 hash 都不得进入 preimage 或 snapshot record；联合批准只能在真实 artifact 生成并复核后另行绑定同一未改字节的 snapshot。
9. 首次 snapshot 后，第 1—8 节任何 byte 变化都必须提升 CR revision、重新生成 snapshot，并清空旧修订全部签名；第 9 节状态更新不改变同一 revision preimage。

本规范正文不随审批进度改写“状态”措辞。合同 snapshot、artifact hash、离线向量、migration 文件或测试通过均不自动授权 Request 同步、网络、真实恢复或 production。
