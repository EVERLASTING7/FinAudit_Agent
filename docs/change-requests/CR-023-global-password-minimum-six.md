# CR-023：全局密码最小长度调整为 6

- 状态：APPROVED
- 批准人：BOSS（YHBX）
- 批准日期：2026-08-17
- 适用范围：所有环境

## 决定

将密码策略从 `auth-password-v1` 升级为 `auth-password-v2`：

- NFC 后最小长度由 15 个 Unicode code point 调整为 6 个；最大长度继续为 128 个 code point，UTF-8 上限继续为 512 bytes。
- 不增加大写、小写、数字或符号组合要求；空格和合法 Unicode 继续允许。
- 创建、重置、强制换密、bootstrap 和登录统一消费该全局策略，不提供环境例外。
- Argon2id、五次失败锁定 15 分钟、Refresh 会话撤销、一次性换密 Token 和日志脱敏边界不变。
- 版本化弱密码黑名单继续生效，并新增 `123456`、`letmein`、`qwerty` 三个常见短弱密码；黑名单摘要随制品更新。

## 原因与影响

BOSS 明确要求所有环境只需至少 6 个字符，以降低 Local MVP 的使用门槛。该决定会降低未来公网环境的密码熵下限，属于显式接受的安全取舍；弱密码黑名单、Argon2id 和锁定策略保留为补偿控制。

现有密码 Hash、用户、角色、会话 Schema 和 API 字段不变，不需要数据库迁移。长度为 6～14 且未命中黑名单的密码将在创建、重置和强制换密时成为合法输入。

## 验证与边界

- 5 个 code point 必须拒绝，安全的 6 个 code point 必须接受。
- `123456`、`letmein`、`qwerty` 必须继续拒绝。
- 128 个 code point 允许；129 个 code point、超过 512 UTF-8 bytes 或含 NUL 的输入拒绝。
- Frontend 的换密、创建用户和重置密码表单显示最小 6 字符，并继续由 Backend 作最终判定。
- 当前本地栈重建后，使用受管恢复密码进入强制换密流程，以 6 字符非弱密码完成换密，再验证普通会话和授权读取。

如果未来恢复更高下限，必须形成新的显式安全决定，并先处理已存在的 6～14 字符密码；直接把最小值改回 15 会使这些用户无法登录。
