# Change Requests 历史与决策资料

本目录不是当前开发规格，也不要求开发者逐份阅读。活跃产品行为、技术边界和实施顺序分别见：

- `Request/PRODUCT_REQUIREMENTS.md`
- `Request/TECHNICAL_SPEC.md`
- `Request/IMPLEMENTATION_PLAN.md`

批准过且仍有效的语义必须已经合并进上述文档或对应机器事实源；未合并、候选、草稿、回执、签名、hash 和 Gate 不能自行成为实现前置。只有活跃规格或当前代码事实可独立复现的歧义，才阻断受影响的最小切片。

本目录暂时保留，是因为部分历史 Schema、Policy 和静态验证代码仍按精确路径读取制品。保留路径不代表这些文件继续定义产品行为。删除或移动前应先解耦实际代码引用并通过相应测试。

只有改变产品范围、已发布外部 API 兼容性、持久化业务语义、状态/权限/安全边界或正式验收阈值时才新增简短 CR。批准后立即更新唯一事实源；不要再生成覆盖旧正文的补丁栈。
