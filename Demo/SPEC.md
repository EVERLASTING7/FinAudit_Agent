# FinAudit Agent 前端 Demo 设计规范

> 这是给多 agent 协作的**共享规范**。所有 demo 都基于此规范实现，但**视觉风格由各自决定**。
> 目标：产出 1 份**单文件 HTML demo**（含全部 14 个页面的静态展示，零功能、零构建），可直接双击在浏览器中打开。

---

## 1. 项目一句话

**FinAudit Agent** —— 企业财务文档智能审核与风险分析平台。审核辅助工具，不替代人工作最终决定。

核心业务闭环：上传文件 → 解析/OCR → 字段提取 & Markdown 转换 → 人工确认 → 合同发票关联 → 制度 RAG → 确定性规则核验 → 风险复核 → 报告导出。

## 2. 强制要求

1. **单文件**：所有 demo 必须是单个 `*.html` 文件，双击即可在浏览器打开，**禁止**任何构建步骤、外部资源（CDN 除外）、npm 依赖。
2. **零功能**：所有按钮、菜单、链接、表单都不需要真实功能。但**点击侧边栏菜单必须切换到对应页面**（用 hash router 或 data-route + JS 即可）。
3. **全部 14 个页面都要做出静态展示**，每个页面都要有真实的样例数据（mock），不能只是空框架。
4. **可滚动**：页面内容超出视口时允许滚动。
5. **响应式**：桌面优先（>=1280px 设计宽度），最小支持 1024px。

- 侧边栏菜单项：工作台 / 文件管理 / 合同管理 / 发票管理 / 合同发票关联 / 制度知识库 / AI 问答 / 审核任务 / 报告 / 用户管理
- 角色 chip 在顶栏用户旁展示（用 finance_reviewer 作为默认演示角色）

## 5. 角色模型（5 种固定角色）

| 代码 | 中文 | demo 默认入口限制（仅用于菜单显隐） |
|---|---|---|
| `system_admin` | 系统管理员 | 全开 |
| `finance_reviewer` | 财务审核人员 | 演示主角色，看不到用户管理 |
| `audit_reviewer` | 审计复核人员 | 看到审核任务/报告/制度审批 |
| `contract_admin` | 合同管理员 | 看到合同/关联/发票只读 |
| `read_only` | 只读用户 | 大部分只读 |

顶栏可以放一个**角色切换器**（切换菜单可见性，不影响 demo 展示）

## 6. 状态标签规范

所有状态用统一的 chip 风格（**文字+底色+小圆点**，不只靠颜色）：

| 状态类型 | 配色 |
|---|---|
| 已存储 / 已确认 / succeeded / 有效 / active | 绿 |
| 进行中 / validating / running / queued | 蓝 |
| 待复核 / pending / ready / review_required | 黄/橙 |
| 失败 / rejected / high / failed | 红 |
| 草稿 / draft / outdated / superseded | 灰 |
| 信息 / notice / 提示 | 青/紫 |

CSS 类名建议：`.status.status-success` `.status.status-info` `.status.status-warning` `.status.status-danger` `.status.status-neutral` `.status.status-pending`

## 7. 关键 UI 元素规范

- **表格**：默认行高 44px，表头灰底，斑马纹，行 hover 高亮，操作列固定右侧
- **按钮**：主操作 `.btn-primary`（深色实心），次要 `.btn-secondary`（描边），危险 `.btn-danger`（红），禁用 `.btn:disabled`（半透明）
- **表单**：标签在左，输入在右，必填加红星
- **金额**：千分位 + 币种符号，如 `¥ 1,234,567.89`
- **日期**：YYYY-MM-DD
- **空值**：统一显示 `—`
- **面包屑**：模块 > 列表 > 详情

## 8. 必须体现的"项目特色"细节

每个 demo 都必须把下面这些**专业感细节**做出来，不能只做"通用后台"：

1. **风险等级**（none/notice/low/medium/high）有 5 档 chip 配色
2. **AI 降级声明** banner（黄色提示："AI 解释不可用，规则结果仍可复核"）
3. **证据追溯**展示（页码 + 原文片段 + 置信度）
4. **执行版本号**（V1 / V2 / V3）
5. **Trace ID** 在错误状态里
6. **状态机复杂**：文件/解析/Markdown 是分开的 3 列状态
7. **审核快照哈希** 类信息（业务感强）
8. **RAG 引用卡片**：制度名/版本/页码/章节/原文片段
9. **拒答态**：AI 问答无答案时不能伪造答案
10. **职责分离**：high 风险最终复核人为审计复核人员

## 9. 视觉风格差异化

3 个 demo 的视觉风格由 agent 自主决定，下面是建议方向（**不要完全照抄，要做差异化**）：

- **Demo A**：经典企业级（深蓝 + 金色点缀，类似金融科技大厂）
- **Demo B**：现代轻量（白底 + 灰 + 蓝紫渐变 + 圆角，类似 Linear/Notion）
- **Demo C**：暗色专业（深色主题，霓虹点缀，类似交易终端/监控大屏）

每份 demo 的 CSS 必须独立完整，不依赖任何外部资源（icon 用 emoji 或内联 SVG）。
